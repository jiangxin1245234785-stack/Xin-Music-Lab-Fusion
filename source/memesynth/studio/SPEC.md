# SPEC — memesynth studio v1（冻结 2026-10-25）

1. **输入**：单个 MIDI（XLD 的 `merged.mid`，也吃任何 SMF 0/1）。拖进浏览器窗口，或把文件拖到启动器图标上。一次一个。
2. **输出**：48 kHz 立体声 24 bit WAV，写到用户指定目录（默认 `work/memesynth-out/`），文件名 `<midi名>.<kit名>.wav`；勾了分轨则另写 `<midi名>.<kit名>.<路由>.wav`。同名文件自动加 `-2`、`-3`，不覆盖。
3. **界面**：本地网页（`localhost`）。控件：拖放区、转谱体检表、片段时间线、八套音色按钮、四个声部开关、播放/暂停、输出目录输入框、音色多选、分轨勾选、导出按钮、进度条、打开输出目录按钮。
4. **目标机器**：用户本机 Windows 11，**复用仓库内 `runtime/0.5.0/envs/basic/python.exe`**，不要求系统装 Python。双击 `音色工作台.cmd` 启动。
5. **失败策略**：单文件工具。某一套音色导出失败只记该套的错误并继续其余，页面逐条显示；解析失败则整体中止并报原因。
6. **依赖红线**：
   - **tkinter 不可用** —— 本仓库的嵌入式 Python 有 `_tkinter.pyd` 和 tcl86t.dll，但缺 Tcl 脚本库（无 `init.tcl`），`Tk()` 直接抛 TclError。GUI 因此走本地 HTTP + 浏览器，不是审美选择。
   - 运行期只用 `numpy` / `soundfile` / `pretty_midi` + 标准库 `http.server`。**不引入 librosa、numba、scipy、ffmpeg**。
   - 试听在浏览器里跑 JS 移植版（已对 31 个真实导出逐音符验证，渲染信噪比 61 dB）；**导出一律走真正的 memesynth**，所以落盘的 wav 与 CLI 逐比特同源。

## v2：人声（冻结 2026-10-27）

把 `source/voiceswap` 的声音库放进工作台，和八套 kit 并列：kit 管乐器，人声管主旋律。

1. **输入**：在 MIDI 之外再拖入同一首歌的人声分轨（XLD 分离出的 `vocals.wav`，和 `merged.mid` 同一时间零点）。一次一首。
2. **声音**：原唱、合成声音库（Seed-VC，`voices/<名>/reference.wav` 在的才列）、社区 RVC 模型（已下载的才列）。点没转过的声音，就在后台转**整首**。
   一次只转一个，其余排队；同一份人声、同一个声音转过就缓存，不重转。
3. **试听**：选中的声音和当前 kit 在同一个 12 秒片段里同步循环。选人声时自动关掉 kit 的「主旋律」声部（那条是转谱出来的旋律，会和人声叠在一起），开关仍可手动改。
   人声音量滑块 ±12 dB，0 dB = 唱的帧上 RMS −20 dBFS。
4. **导出**：选了人声就为每套 kit 再写一个 `<midi名>.<kit名>.<声音名>.wav`（乐器去掉主旋律路由 + 人声，居中），音量按滑块，峰值超 −1 dBFS 时整体压一个因数。勾了分轨就另写 `<midi名>.<声音名>.vocal.wav`。
5. **失败策略**：转换失败只标这个声音，其余照常；人声没转好就导出，只导乐器并在日志说明。
6. **依赖红线**：工作台自身仍只用 `envs/basic`（numpy / soundfile / pretty_midi）。转换、折单声道、重采样到 48 kHz 都在 `envs/highres` 的子进程里做（`voiceswap/studio_bridge.py`），工作台不 import torch / librosa / soxr。
   缓存在 `work/memesynth-cache/voices/<人声 sha256 前 16 位>/`，不写 XLD 的分析目录。

## v5：按轨重构（冻结 2026-11-11）

用户：「人声只是轨道的一部分，我的核心是完成分轨后重构」。看过以轨道为中心的草图后说「可以，照着做」。v4 的四步界面被这一版取代。

1. **六条轨**，和 XLD 的分轨一一对应：鼓 / 贝斯 / 吉他 / 钢琴 / 其他 / 人声。转谱的路由归到第一条匹配的轨，剩下的归「其他」
   （页面 `trackOf` 和 `batch.track_of` 是同一套规则）。原来的四个声部（鼓 / 贝斯 / 和声 / 主旋律）没有了。
2. **每条轨三选一**：原声（直接用 XLD 分出来的那条音轨）/ 换（乐器轨换一套 kit，人声轨换一个声音）/ 静音。再加音量（−18…+6 dB）和独奏。
   没有分轨的不能选原声（拖进来的 MIDI 全都不能），没有转谱的乐器轨不能选换。人声轨默认原唱。
3. **整套预设是起点**：选一个预设，所有「换」且没有单独指定 kit 的轨跟着它；单独指定过的不受影响。键盘 1–8 切预设。
4. **留原声的轨对齐音量**：把原声缩放到「预设来演这条轨」的 RMS（试听按 12 秒窗口算，导出按整首算）；这条轨在预设下没有声音可比时，
   取其他留原声轨的系数的中位数，都没有就是 1。这样只留一条轨不会打乱其余的平衡。
5. **原曲 / 重构对照**：底部一个开关，原曲 = 六条分轨原样相加，再整体缩放到和当前重构听到的 RMS 一样。原曲不受音量滑块影响，但受独奏影响
   （可以单听一条轨的原声对重构）。只有从曲库打开、有分轨的歌才有。
6. **人声是其中一行**。声音库是从这一行点开的面板（分组和折叠规则不变）。MIDI 里有转谱旋律时，面板里多一项「乐器演主旋律」。
7. **方案**：每首曲库里的歌自动记住上次的选择（`work/memesynth-cache/plans/songs/<编号>.json`），重新打开时恢复；
   「存为方案」起名存一份（`plans/named/`），「套用方案」拿到别的歌上用，对不上的轨自动退到能用的选项。
8. **导出**：一个 `<歌名>.重构.wav`，可选每条出声的轨各一个文件，另写一个 `<歌名>.重构.json` 记下这份方案和每条轨实际是谁演的。
   走真正的 memesynth；整个文件只乘一个系数压到 −1 dBFS，所以分轨相加等于总混音。原来「按 kit 各导一份」从界面上拿掉了，命令行还在。
9. **布局**：左栏曲库常驻，中间轨道表，底部固定播放栏，标题栏一行任务状态和导出按钮。转谱体检折叠在轨道表下面，哪条轨有力度问题在那一行标出来。
10. **依赖**：不加新依赖。导出要把分轨从 44.1 kHz 转到 48 kHz，用 numpy 写的加窗 sinc 多相重采样（`batch.to_48k`）；试听用浏览器自带的重采样。
11. **不做**：分轨和转谱（XLD 的事）、改音符、效果器、训练模型。

## v8：听整首，原声按整首对齐（冻结 2026-11-11）

用户说「推进吧」，没有指定做什么；这两项是我定的，理由写在下面。

1. **听整首**：播放栏上的「听整首」打开一个抽屉，「渲染整首」把现在这份方案整首渲染成一个文件（`work/memesynth-cache/listen/`，只留最新一个），
   在抽屉里用播放器从头听、随便拖。和导出是同一个 `rebuild`，听到的就是会导出的。方案改过以后会提示要重新渲染。整首和 12 秒循环不同时出声。
   理由：重构工具只能听 12 秒循环的话，想听整首只能先导出再去别处打开。
2. **留原声的轨按整首对齐音量**（改了 v5 的第 4 条）：系数 = 预设来演这条轨的整首 RMS ÷ 这条分轨的整首 RMS，由服务端量（`/api/levels`，每首歌每套预设量一次，约 2.5 秒），
   试听和导出用同一组数。理由：在七里香上量过，按 12 秒窗口算的话，鼓 / 贝斯 / 吉他和整首的差在 ±2–3.5 dB 以内，
   但钢琴和「其他」在分轨近乎无声而转谱有音符的窗口里会差到 +70 dB，等于把串音放大成噪声。
3. **原曲对照**跟着改：原曲六条分轨统一乘上各轨系数的中位数，不再逐窗口对齐响度。原曲里安静的段落保持安静。

## v9：鲁棒性（冻结 2026-11-11）

用户：「主要做一下三。保证一下软件的鲁棒性」（三 = 工作台里没做或没验证的）。这一版不加功能，只让已有的东西经得起意外。

1. **出错要说出来**：服务端任何一个请求里的异常都回一句 JSON 的错误（以前异常会直接断开连接，页面误报「连不上服务」）；
   页面里渲染失败、没接住的异常都写到状态栏。
2. **文件在脚下变了能恢复**：XLD 重新合并或重新分离以后，旧路径不在了，服务端自动重扫曲库再找；音量的测量结果跟着文件的修改时间走，文件变了就重量。
3. **空的分轨不放大**：一条分轨整首低于 −60 dBFS 算空的，不按它自己的比例放大；其余分轨的放大倍数不超过各轨中位数的 4 倍。界面在那一行标出「这条分轨是空的 / 几乎没声音」，导出结果里也写。
4. **坏的方案不会让导出失败**：方案里认不出的模式、不存在的 kit、不是数字的音量，各自退回默认值；页面套用方案时同样过滤。全部静音的方案明确拒绝。
5. **服务跟着页面活**：页面每 4 秒报一次平安，关闭时说一声再见。没有页面在用、也没有转换和导出在跑，服务才退出：
   收到再见后约 10 秒；没收到（比如崩溃）就等 150 秒没动静；启动后 45 秒一直没有页面来也退。不再盯浏览器进程（配置已在运行时它会立刻退出，靠不住）。
6. **启动失败有弹窗**：双击启动而起不来时弹一个消息框说明原因，详情在 `work/memesynth-cache/studio.log`（超过 1 MB 自动重开）。
7. **工作台开着时再把 MIDI 拖到启动器上**：文件交给已经开着的那个，几秒内载入。
8. **自动测试**：`studio/tests/test_studio.py`，14 项，全部在临时目录里造数据，不碰 XLD 的分析目录和工作台的缓存。

## v11：六套电子预设（冻结 2026-11-11）

用户：「先来电子的，我全都要（握拳）！」。全部是 numpy 合成，没有下载任何素材；配方在 `tools/kitdefs/`，`make_kits.py` 随时重建。

| kit | 是什么 | 靠什么成立 |
|---|---|---|
| synthwave | 80 年代 | Juno 式贝斯（滤波器 0.1 秒内关上）、三锯齿复音铜管、门限混响军鼓 |
| supersaw | Trance / EDM | 每个音七个不等距失谐的锯齿；909 底鼓 + 拍手 |
| trap | 808 | 贝斯就是拉长、过载的 808 底鼓；六个方波做的金属镲；哨音主音 |
| lofi | 磁带 | 所有有音高的声部过「磁带」（走带不稳、没高频、饱和、底噪），鼓过 12 位 + 半采样率 |
| glitch | 故障 | 位数不够、参数乱跳、包络重触发；波形周期不动，所以音高是对的 |

## v14：按需载入、每轨调整、两套预设对比（冻结 2026-11-12）

用户离开前选的四项：「预设按需载入、每轨效果器、每轨移八度和力度、两套预设快速对比」，回来一起验收。

1. **预设按需载入**：打开时只取预设的目录，不取素材。一套音色第一次被用到（整套预设，或某条轨单独指定）才下载、解码，之后留着。
   对比里的另一套会在后台先载好，切过去不用等。服务端不再让浏览器缓存任何文件（重建过的 kit 立刻生效）。
2. **每条轨一个「调」按钮**，点开五个滑块，存在方案里（只存动过的，旧方案照常能读）：

   | 滑块 | 范围 | 做什么 | 对谁有效 |
   |---|---|---|---|
   | 八度 | −2…+2 | 这条轨的音符整体移八度 | 换了音色的轨；鼓没有八度 |
   | 力度 | −100…+100 | 每个音的力度离这条轨的平均值更近（压平）或更远（夸张），倍数是 2^(值/50) | 换了音色的轨 |
   | 明暗 | −100…+100 | 负数是低通（18 kHz 降到 250 Hz），正数是高通（30 Hz 升到 2.5 kHz） | 所有出声的轨 |
   | 回声 | 0…100 | 0.3 秒一次、每次剩 40% 的回声 | 所有出声的轨 |
   | 混响 | 0…100 | 1.8 秒的房间 | 所有出声的轨 |

   「原曲」对照不受这些影响（它是参照物）。
3. **试听和导出必须一样**：页面用 Web Audio 的节点边放边做，导出（和「听整首」）由 `effects.py` 算。滤波用的是 Web Audio 自己的 biquad 公式，
   房间是服务端生成的同一个脉冲响应（页面从 `/reverb.wav` 取），回声按浏览器反馈回路的实际行为算（每圈多 128 个采样）。
4. **两套预设对比**：最近选过的两套预设出现在预设栏下面，标成 A / B，点一下或按 `` ` `` 在同一个播放位置来回切。
   「存成两个方案」把现在的方案分别配上这两套，存成「<歌名> · <预设>」两份。
5. 测试实例（8790 / 8791）改用自己的方案目录 `work/memesynth-cache/plans-dev`（`server.py --plans`），不再和用户的方案混在一起。

## v15：人声效果跟随预设（2026-11-12，等验收）

用户问人声要不要也有和乐器预设配套的东西。定下来分两层，这一节只是第一层：复用 v14 的明暗 / 回声 / 混响。
第二层（声码器、变调、降位数）不在这里。

1. **一张表**：`effects.py` 的 `VOCAL_PRESETS`，每套预设给人声一组明暗 / 回声 / 混响（比如 lofi −45/0/15、ambient −15/30/70、chiptune +20/0/0）。
   表里没有的预设是 0/0/0。页面从 `kits.json` 的 `vocal` 字段读同一份数，不另存一份。
2. **规则**：人声轨的方案里多一个 `follow`。为真时，人声的明暗、回声、混响取**整首预设**的那一组（不看某条轨单独指定的音色），八度和力度还是自己的；
   为假时用自己的五个数。旧方案没有 `follow`：自己的明暗、回声、混响都是 0 就跟随，有一个不是 0 就不跟随（手调过的不变）。
   原唱、换过的声音、乐器演主旋律都一样；「原曲」对照不受影响。
3. **导出**：`batch.rebuild` 用 `effects.vocal_settings`；写出的方案记 `follow` 和人声自己的数，报告（`written`）记 `follow` 和实际用上的数。
4. **页面**：人声那一行的「调」面板最上面有「跟随预设」勾选框。勾着时明暗、回声、混响三个滑块显示预设的值、不能拖；
   取消勾选后滑块从刚才显示的值开始，可以拖。「复位」重新勾上。按钮在实际用上的值不为 0 时亮，提示写「跟随预设 <名字>」。播放中换预设，人声跟着变。

## v16：编曲地图（2026-11-12，等验收）

用户想在自己编曲之前先看懂别人怎么编：谁什么时候在弹、谁停了、每件乐器有多忙、在什么音高上。

1. **位置**：底部播放条里原来那条灰色的密度条，变成整首歌的编曲地图（高一些，72 像素）。12 秒的窗口框和「点一下挪窗口」照旧。主页面仍然一屏放得下。
2. **六条道**：从上到下是鼓、贝斯、吉他、钢琴、其他、人声，各用自己那条轨的颜色。关掉（静音）的轨那条道变暗，再打开就亮回来。
3. **一格是一小段时间**：横向大约 3 像素一格，一格代表整首歌长度 ÷ 格数的那几秒。
4. **有音高的乐器**（贝斯、吉他、钢琴、其他，以及有转谱的人声）：每格一小条，**越亮**表示这一段时间里这件乐器响着的时间越满；只有一个很短的音也至少看得见。
   **越高**表示这里弹的音越高，按这件乐器自己在整首里的最低音到最高音算，所以每条道都用满自己的高度。没声音的地方空着。
5. **鼓**：没有音高，分三行，从下到上是底鼓、军鼓、其余（踩镲、吊镲、嗵鼓）。越亮这一段敲得越密（和这一行最密的那段比）。
6. **人声没有转谱时**（通常如此）：画的是原唱的响度，一条居中的带子，越亮越响（和最响的那段比），比最响低 45 dB 以上的地方空着。人声还没载入时这条道是空的。
7. **看法**：鼠标停在地图上，显示那一刻的时间和谁在响，比如「1:42 · 鼓 贝斯 钢琴」。说明面板里加了一句。
8. 地图只是看的，不改任何声音。

## v17：掷骰子（2026-11-12，等验收）

用户常常不知道自己想听什么：点一下，给一整份自己不会去选的重构，能马上听；不喜欢就再掷，喜欢的能退回去。

1. **两个按钮**，在「存为方案」和「套用方案」后面：「掷骰子」（骰子图标，键 `D`）和「上一份」（键 `Z`）。在输入框或下拉框里打字时这两个键不起作用。
2. **骰子会换的**：
   - 整首的预设：30 套里随便一套，但不会是现在这套。
   - 鼓、贝斯、吉他、钢琴、其他（有转谱的）：四分之一的机会留原声（这首有这条分轨时），否则换。换的轨：六成跟随预设，四成另换一套音色；
     七成不动八度，其余高或低一个八度（鼓没有八度）；力度压平、不动、不动、夸张四选一。
   - 每条出声的轨：明暗、回声、混响各有七成是 0，其余随机（明暗 ±5…±40，回声 10–40，混响 10–50）。
   - 人声：自己的明暗、回声、混响清掉，改成跟随新预设。
3. **骰子不碰的**：关掉（静音）的轨原样不动；没有转谱的轨不改谁来演；人声是原唱还是哪个声音不变（换声音要几分钟）；每条轨的音量不变。所有轨的「独奏」都取消。
4. **上一份**：每掷一次，掷之前的那一份记下来（最多 20 份），「上一份」一份一份退回去。换一首歌就清空。没得退时按钮是灰的。
5. **掷出了什么**：按钮下面一行写「掷出：techno · 贝斯 reese · 鼓 留原声 · 钢琴 高八度」——预设，加上和「全都跟随预设、什么都没调」不一样的地方，太长就用 … 截断；
   底部状态栏只写「掷出：<预设>」。掷出来的方案和手动选的一样：自动保存、A / B 对比里是掷之前和掷出来的两套预设。
6. **（v18，2026-11-12）换预设不等**：有留原声的轨时，换到一套这首歌还没量过的预设也马上出声：留原声的轨先用这首歌量过的另一套、按两套音色每条轨的响度差（`kits/levels.json`）换算过来的音量，
   几秒后量好了再悄悄换成准的（不从头放），这期间状态栏末尾写「· 原声音量校准中」。一首歌第一次打开还是要等一次（几秒）。

## v19：长短、前后、松紧、疏密（2026-11-12，等验收）

为了让用户一次只拧一样、听同一段音符怎么变。每条轨的「调」里多四个滑块，和八度、力度一样只对换了音色的轨有效、存在方案里、试听和导出一样：

| 滑块 | 一头 | 另一头 | 做什么 |
|---|---|---|---|
| 长短 | 短（−100：只剩四分之一长） | 长（+100：四倍长） | 每个音的长度 × 2^(值/50)；最短 30 毫秒；拉长时不会盖过同一个音的下一下。鼓没有这一项 |
| 前后 | 赶（−60 毫秒） | 拖（+60 毫秒） | 整条轨提前或推后，最早到 0 秒 |
| 松紧 | 准（0） | 松（100：±30 毫秒、力度 ±20） | 每个音一点点不准；每次都一样（由这个音本身算出来，不是随机抽签） |
| 疏密 | 满（0） | 疏（100：去掉七成） | 去掉最轻的那些音（同样轻先去短的、再去靠后的） |

一条轨里的先后：先疏密，再八度和力度，再长短，再前后，最后松紧。面板分两栏：「音符」（八度 力度 长短 前后 松紧 疏密）和「声音」（明暗 回声 混响）。
掷骰子：换了音色的轨，长短两成机会 ±50，疏密一成半机会 30 或 60；前后和松紧骰子不碰。

## v20：抽吸（2026-11-12，等验收）

每一下底鼓把贝斯、吉他、钢琴、其他压下去，再慢慢放回来（侧链的那种「呼吸」）。鼓和人声不动，「原曲」对照不动。

- 按钮「抽吸」在预设栏第二排、「上一份」后面，开着时变色；点开两个滑块：**深度** 0（不抽）… 100（最深压掉八成），**恢复** 60 毫秒（很快回来）… 400 毫秒（很慢）。整份方案一个设置，开着才存。
- 跟的是实际演奏的底鼓（底鼓被「前后」挪了，抽吸也跟着挪）；鼓那条轨静音了也照样抽；留原声的轨也抽。先抽吸、再明暗 / 回声 / 混响，所以混响会从压下去的地方继续响。
- 转谱里没有底鼓的歌，按钮是灰的，提示写着为什么。
- 掷骰子：三成机会开抽吸，深度 30 / 50 / 70，恢复 150 或 250 毫秒。
