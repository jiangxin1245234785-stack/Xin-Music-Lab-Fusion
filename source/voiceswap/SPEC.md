# SPEC — 人声音源替换 v1（Phase 0，2026-10-26，**未冻结**）

目标：把一首歌的人声**换成另一个声音**，保留演唱本身（音高、节奏、咬字、情绪）。
不是转谱：L1 的 `vocals-pyin` 把人声变成 MIDI 再用合成音色重奏，用户 2026-10-26 明确说
那不是他要的。

1. **输入**：BS-RoFormer 分离出的 `vocals.wav`（已有，六轨之一，干净单声部，正是 VC 最理想的输入）。
2. **输出**：同长度、同采样率的人声 wav；再与其余五轨相加还原整曲。保留绝对秒时间轴。
3. **界面**：先命令行（`memesynth.cmd` 加一条，或独立入口）。图形界面等听感确认后再说。
4. **目标机器**：本机 RTX 5070 Ti Laptop / 11.9 GiB VRAM / torch 2.11+cu128 / CUDA 可用 / D 盘余 168 GB。推理足够；训练另算。
5. **失败策略**：单文件工具，失败整体中止并报原因。长任务留 progress 回调。
6. **依赖红线**：**第三方代码与权重一律不入库**，沿用 drumsep-v1 / muscriptor-v1 的办法——放 `runtime/addons/`，由 `XLD_*_ROOT` 定位，适配器核验 sha256。

## 已定（2026-10-26 用户选择）：两种目标声音，因此两套后端

- **B 合成声音库** —— 用 TTS 造一批音色当参考，做成和八套 kit 并列的「人声库」。走**零样本**：
  加一个声音＝丢进一段参考音频，不训练。→ 引擎 **Seed-VC**
- **D 现成社区 RVC 模型** —— 用户明确点头。走 **RVC 推理**。→ 引擎 **Applio（MIT，代码+权重）**。
  这类模型多数没有明确许可、目标是可识别的真人歌手；登记表要逐个写明来源与许可未知，
  自用播放与对外发布是两件事。

两套后端共用一个适配器接口（输入 `vocals.wav` + 目标标识 → 输出同长 wav），和 XLD 里
多个 MIDI 后端共用 runner 是同一个形状。先做 B（不用训练，最快能听），再做 D。

## Phase 0 可行性：Seed-VC 能不能在这台机器上跑

**它自带的 requirements 不能用。** `requirements.txt` 钉 `torch==2.4.0`，而本机是
**RTX 5070 Ti Laptop / sm_120（Blackwell）**；torch 2.4 的 arch list 到 sm_90 为止，装上去
显卡根本不被支持。必须让它跑在现有的 `envs/highres`（torch 2.11.0+cu128，arch list 含
sm_120）上，**跳过它的 torch 钉**——也就是 MuScriptor v0.4 的 `--target --no-deps` 同一套办法。

跨版本静态核查（代码已 clone，未执行）：

| 项 | seed-vc 钉 | 本机 highres | 核查结果 |
|---|---|---|---|
| torch | 2.4.0 | 2.11.0+cu128 | **必须用本机的**，否则 sm_120 不支持 |
| numpy | 1.26.4 | 2.4.6 | 全仓库**搜不到** numpy 2 已移除的别名（`np.float`/`np.int`/`np.NaN`…），风险低 |
| torchaudio | 2.4.0 | 2.11.0 | `inference.py` 只用 `functional.resample`、`compliance.kaldi.fbank`、`save` —— **三个在 2.11 里都还在** |
| librosa / scipy / transformers | 0.10.2 / 1.13.1 / 4.46.3 | 0.11.0 / 1.18.0 / 4.51.1 | 次版本差异，未见已知破坏 |
| 缺失的包 | — | — | **只缺 `munch`**（`pydub`/`onnxruntime`/`faster_whisper`/`langid`/`dac` 只在网页界面、实时和 v2/ASR 路径上） |

SVC 模型是 `seed-uvit-whisper-base`，**44100 Hz**、200M 参数，首次推理自动从 HuggingFace 拉。
命令形如 `inference.py --source <人声> --target <参考> --diffusion-steps 30 --f0-condition True --fp16 True`。
原作者在 RTX 3060 Laptop 上能实时，本机显卡更强、11.9 GiB 显存充裕。

## Phase 0 实跑结果（2026-10-26，用户授权后）：**链路通，用户听过确认**

静态推断全部兑现。七里香的 `vocals.wav` 切 30 秒做源、另切 10 秒做参考（都按能量选段，
避开乐句间的静音），恒等转换实跑：

| 项 | 结果 |
|---|---|
| 跑通 | 30 步扩散，**48.8 s 墙钟 / RTF 0.77**（快于实时），输出 29.99 s @ 44100 Hz |
| 显存 | 11.9 GiB 够用，torch 2.11+cu128 在 sm_120 上正常 |
| 音色 | 平均频谱相似度 **0.928**（同一人进、同一人出） |
| 旋律 | 折叠八度后相关 **0.999**，50 音分内 **96.1%**，真跑调帧仅 **1.0%** |

实际用到的装配（和 MuScriptor v0.4 同一套路数，第三方代码权重都不入库）：

1. upstream clone 到 `runtime/addons/seedvc-v1/upstream`。**权重 2.4 GB 落在
   `upstream/checkpoints/`，不在仓库的 HF 缓存里**——`inference.py` 第 5 行在 import 时就把
   `HF_HUB_CACHE` 改成了相对路径 `./checkpoints/hf_cache`，HF_HOME 管不住它。两个后果：
   权重正好落在 addon 目录（符合约定，仓库 HF 缓存没被动过），以及**任何调用方都必须先
   chdir 到 upstream**，否则找不到权重
2. 缺的包 `--target runtime/addons/seedvc-v1/deps --no-deps`：`munch` 只是开头，实际还缺
   `dac` / `audiotools` / `markdown_it` / `tensorboard` / `docstring_parser` 一长串
3. **`--target` 会顺带拖进 numpy 2.5.4**，会遮掉 env 自己的 2.4.6 并打断 numba/librosa ——
   装完必须把 `numpy` / `setuptools` / `_distutils_hack` / `*.pth` 从 target 目录剪掉
4. `._pth` 让解释器忽略 PYTHONPATH 也不加脚本目录 → 路径在代码里插，见 `scratchpad/run_seedvc.py`
5. **torchaudio 2.11 的 `save` 已改走 TorchCodec**，没装就 ImportError。模型本身在 2.11 上跑得好，
   只有最后写文件这一行会炸 → 在启动器里把 `torchaudio.save` 换成 soundfile，不改归档的 upstream

### 教训：这道闸门差点被自己的尺子否掉

第一版客观检查判了**不通过**（音高相关 0.325，阈值 0.8）。实际是**尺子错了**：

- 分歧帧里 **40.0% 恰好差一个整八度**，真跑调（100–600 音分）只有 1.0%
- 八度分歧**100% 是同一个方向**（输出偏高）——单向偏差是测量错，不是模型错
- pyin 置信度 源分轨 **0.21** / 转换输出 **0.69**，低置信的那一边才是可疑的一边
- 直接问频谱：分歧帧上源分轨在**高八度**更强 **168 帧** vs 低八度 34 帧

即 pyin 在分离出来的人声上锁到了次谐波，把**源**读低了一个八度；转换输出是对的。
（提高 `fmin` 无效：这歌的次谐波落在 110–290 Hz，本来就在 fmin 之上。）

**连带发现（未处理，另案）**：`analysis-midi/vocals.py` 的转谱走的是同一个 pyin、同一条分轨，
同样会吃到这个八度错。`correct_octaves()` 用块中位数能救掉块内零散的错，但错到 40% 的量级上
值得单独复核。用户已明确转向音源替换，故此处只记录不动。

### 全库实测（18 个各转一遍 30 秒源人声，161 s 跑完）

- **音色 18/18 都真的换掉了**：相对原唱 campplus 0.138–0.552，基准（没换）是 0.786。
- **旋律 18/18 完好**：折叠八度后相关全部 0.999，50 音分内 96.1–97.3%。
- **但转换结果比参考更靠拢**：参考两两平均 0.294 → 转换后 **0.474**。源的旋律、咬字、
  气口是共同约束，会把不同音色往一起拉。

所以**听感上的有效声音数少于 18**。五对超过 0.75，大概率分不开，且基本都是男声对男声：

| 对 | 参考时 | 转换后 |
|---|---|---|
| xiaoyi – yunxia | 0.686 | **0.811** |
| wanlung – christopher | <0.49 | **0.796** |
| yunjian – connor | — | 0.752 |
| xiaobei – sunhi | 0.529 | 0.751 |
| yunjian – yunyang | 0.637 | 0.750 |

规律：**离原唱音区越远，换得越开**。女声/童声（xiaoni 0.138、yunxia 0.179、xiaobei 0.194）
移动最大；低沉男声最小（christopher 0.552、wanlung 0.468、connor 0.465）——源本来就是男声。

听评结论：**耳朵分得开**，用户原话「所有的不同的人声分离度挺高的，我很满意」。campplus 的
0.75 线对这个库偏严，五对都不砍，`--cfg-rate` 也不调。

### 和声把音高拽低一个八度（2026-10-26 听评报出，已修，用户听过确认）

用户听评：「就像雨水」的「水」，原曲有低沉的和声，所有声音一起跑偏。定位（whisper 对词 +
逐 0.1 秒音高）：「水」在片段 12.0–12.3 秒（原曲 251.0 秒），那里有一条**低八度的和声**，
Seed-VC 的 RMVPE 锁到了它，18 个声音全部把「水」唱低一个八度。

**先试的「分开主唱与和声」走不通**——XLD 已装的 Mega 53（`refine-roformer-v1`）四种用法全不合格：

| 用法 | 主唱增益 | 其余里残留的主唱 | 和声进其余？ |
|---|---|---|---|
| 人声分轨 → lead-vocal 头 | 1.59 | −2.0 dB | 否 |
| 混音 → lead-vocal 头 | 1.40 | −2.2 dB | 否 |
| 混音 → back-vocal 头 | 0.73 | −9.3 dB | 一处略有 |
| 人声分轨 → back-vocal 头 | 0.80 | −11.5 dB | 否 |

主唱头在两种输入下都放大 1.4–1.6 倍、其余是反相副本（相关 −0.92），问题在头本身而不是输入；
和声头漏得太多（要 −20 dB 以下，原唱才不会漏回来）。为此写的 `split.py` 已删除。

**改为修转换用的音高曲线**：`swap.py` 的 `lift_octave_dips()`，在缓存模型时把 RMVPE 包一层，
只作用于源人声（按时长认），upstream 不改。按「音」比较：曲线在断开处和相邻帧跳超过 4 个
半音处切开，某个音 ≤0.6 秒、中位正好比前一个音低一个八度（±1）、之后是换气或立刻回原位，
就抬回原八度。按「帧」比的第一版漏掉了「水」——RMVPE 是 D#4、断一帧、再从 E3 滑进 D3。
`--keep-octaves` 关掉，`--selftest` 跑 6 种形状。

实测：七里香片段抬回 10 处、共 0.67 秒（「水」12.10–12.36 秒 + 0.66–0.80 秒一处 + 8 处几帧毛刺）。
18 个声音一起下坠的地方从 **4 处降到 2 处**，剩下的 26.02 秒是旋律本来就下行（原音已停，−16 dB），
8.53 秒是换气后乐句起音的滑音，都没动。

代价：被抬回的那一下，转出来只剩一条主唱，那条低八度和声在转换结果里没有了。要连和声一起保留，
需要一个真正能分主唱/和声的模型（专门的 karaoke Mel-RoFormer 之类），见 backlog。

试听台第 2 版加了「修正后 / 修正前」开关（同样是同一时钟上的增益切换，修正前那组点到才载入）
和「重点听这几处」（`swap.py` 写出 `<源>.f0-repairs.json`，`make_bench.py --before --mark` 读）。
用户听第 2 版后确认「水」修好了（在对话里答复，页面上没标）。

### 探针结论（先验证前提，再铺开 18 个）

拿 3 个差异最大的参考端到端跑了一遍，回答了三个铺开之前必须先定的问题：

1. **TTS 说话参考能当歌唱音色用** —— 能。音色相对原唱（campplus）：晓晓 0.225 / 云健 0.390 /
   七海 0.297，而"音色没换"的基准（恒等转换）是 **0.786**。彼此之间 0.324–0.604，分得开。
2. **旋律不受参考影响** —— 四个参考全都是折叠八度后相关 0.999、50 音分内 96–97%。
3. **放慢参考没用** —— `-35%` 和正常速度的结果 campplus 相似度 **0.976**，就是同一个声音。
   这条复杂度不加，已写进 `voices.py` 以免有人再试。

### 又一次：差点被自己的尺子否掉（第二回）

平均频谱相似度说四个转换全都 0.917–0.927 距原唱，而恒等转换是 0.928——读起来像"参考完全
没起作用"。**是尺子钝**：30 秒同一首歌、同样的字、同样的强弱，平均频谱主要反映的是歌，
不是人。换成模型自己条件化用的 campplus 说话人编码器，结论完全相反（见上）。

教训固化为做法：**判断音色，用模型自己的说话人编码器，不要用频谱统计量。**

## Phase 2：D 社区 RVC 模型（2026-10-26，接通 5 个；10-27 听评后删掉毛白灵，留 4 个）

| 文件 | 作用 |
|---|---|
| `rvc_models.py` | 模型目录——**保留的东西**。每条钉仓库 revision 和下载物的 sha256，记 `license` / `who` / `octave` |
| `fetch_rvc.py` | 下载到 `<addon>/models/<名>/`（`model.pth` + `model.index` + `model.json`）。逐个核 sha256；压缩包不解压，只按名读出那一个 `.pth` 和 `added_*.index`；checkpoint 用 `weights_only=True` 打开，带代码的 pickle 直接拒。用 `python -I` 跑 |
| `rvc.py` | 分轨 + 模型名 → 换完的 wav。输出命名、长度、采样率与 `swap.py` 一致，所以 `make_bench.py` 能把两套放进同一页 |

**引擎：Applio 3.7.1**（MIT，tag 当天发布，commit `6f69726b`，装在 `runtime/addons/applio-v1/upstream`，
`XLD_APPLIO_ROOT` 可改）。**只用它的推理核心 `VoiceConverter`**，不装 Gradio 应用：

- `envs/highres` 正好满足 Applio 自己钉的 torch 2.11 / numpy 2.4.6 / librosa 0.11 / scipy 1.18。
  只缺三个：faiss-cpu（索引）、torchcrepe（`pipeline.py` 顶层导入）、onnxruntime（Swift 音高器在
  导入时就要），`--no-deps --target` 装进 `addons/applio-v1/deps`。transformers 不跟它升 5.x，
  4.51 加载 contentvec 没问题。
- 权重：`rmvpe.pt` 和 Seed-VC 那份**逐字节相同**（sha256 一致），直接拷；contentvec 从
  `IAHispano/Applio` 下。`rvc.py` 每次核这两个的 sha256 和 upstream commit。
- Applio 会读、并在 `%APPDATA%\Applio` 下新建一个设置文件。`rvc.py` 用 `APPLIO_CONFIG_FILE`
  把它指到 addon 里：另装的 Applio 的设置（比如高音区修正）不会混进渲染，也不往 addon 外写东西。

**模型只从训练者本人的仓库取。** 批量搬运账号 `binant/*` 抽查 3 个，2 个标签是错的：它的

（`RegalHyperus/DrumKitRVCModels/SkyfallDrums.zip`、`SevenDrums.zip`）。标错只有听了才知道，
所以来源先查。

起步 5 个：毛白灵（中文女声，Apache-2.0，训练数据全是 index-tts 合成，无真人录音）、初音未来

**移调只按八度。** 换完要回到其余分轨上，不能离调。RVC checkpoint 里不记训练音域，所以按模型
是谁来定：女声模型升一个八度，男声原调（`octave` 字段，`--octave` 可整体覆盖）。Applio 自带的

混音补回转换拿走的三样：
- **响度**：按原唱「在唱」的 50 ms 窗（最响窗以下 40 dB 内）的 RMS 对齐。转换结果差 −3 到 +1.5 dB。

  开头没有偏移。补零即可。

和伴奏里的分离残留相消，峰值到 1.66。共用一个增益，A/B 比的才是声音而不是音量。
