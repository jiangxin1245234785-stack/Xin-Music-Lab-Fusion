# Xin Music Lab · {{VERSION}} · Windows 界面预览

本包提供 XLD / XML 交互界面和模型接入接口，不包含模型权重、Python 或 AI 依赖。

## 启动

1. 将整个 ZIP 解压到可写目录，不能直接在压缩包里运行。
2. 打开 XLD.exe：选择曲库，浏览与播放本地音乐。
3. 打开 XML.exe：使用音乐可视化。
4. 按 F1 查看帮助；需要分轨/MIDI/段落/和弦时，阅读 MODEL-SETUP.md，自行安装对应模型及依赖，并修改 runtime.json。

没有模型时，分析卡片显示不可用，这是正常状态。只需安装想用的后端，不要求一次装全。仅下载一个权重文件仍不足以运行，模型对应的 Python 依赖也需要安装。

不包含音乐、生成结果或开发者设置。缺少的运行路径不会阻止打开界面。模型由作者提供，请自行从上游下载并完成所需授权；本项目不提供模型镜像或共享账号。

## 范围

这是 core.26 / stems.11 验证基线的界面发行包，模型默认以随包 models.json 为准；不包含此后尚在迭代的引擎。Windows x64 本机界面验收；不是已完成全新 Windows、所有 GPU 与全部模型验收的稳定版。

保留完整目录移动程序；用户曲库和分析结果位置独立。模型自配说明属于接入文档，不是全自动安装器。程序未签名。遇到问题请提供版本与操作步骤，不要提交访问令牌或完整音乐。

# 模型自配说明

适用：0.5.0-preview.ui.1（core.26 / stems.11）。应用只提供工作台和接入接口；模型、Python、GPU 依赖与授权由使用者自行准备。文中路径相对于解压目录。其他开发版的默认或新后端可能不同，请以随包清单为准。

## 先明确三件事

- 不安装模型也能打开 XLD/XML、选曲、播放和使用音频可视化。新建分轨、MIDI、段落与和弦分析需要对应后端。
- 安装 Python 依赖和下载权重是两步；权重版本、文件名与哈希须匹配随包清单，不能只把任意模型丢进目录。
- 本项目不代为接受条款，不镜像受限权重。需要授权时使用本人账号在上游办理，令牌不要写进 runtime.json 或提交 GitHub。

## 配置方式

关闭应用，编辑程序旁的 runtime.json，修改 paths 中所需项；保留其他占位项，未装的模型继续不可用。路径以 runtime.json 所在目录为基准，可用相对路径，也可用自选的绝对路径。JSON 中 Windows 路径建议使用正斜杠，例如 E:/MusicTools/venvs/basic/Scripts/python.exe。应用启动会将这些项传给后端，不能只设置同名系统环境变量后仍保留错误的 JSON 路径。

例如 Basic Pitch 的 Python 装在程序旁 user-runtime/basic：

~~~json
"XLD_MIDI_PYTHON": "user-runtime/basic/Scripts/python.exe"
~~~

这只展示需要修改的一项，不是完整配置文件；不要用它覆盖整个 runtime.json。重启 XLD 并刷新模型卡片。一个后端就绪时可先使用它；“检查环境.cmd”仍可能报告其他未安装项，不能把它理解为所有功能都不可用。

## 各后端约定

### Basic Pitch

先依照 Spotify 说明创建独立 Python 环境并安装 basic-pitch==0.4.0，以及本包 runner 所需的 soundfile、numpy、pretty_midi、mido、onnxruntime。安装依赖可能同时从上游获取其模型。requirements.lock 是开发机锁定记录，不是对所有 Python/CUDA 版本的兼容承诺。将 XLD_MIDI_PYTHON 指向该环境的 python.exe。

可用自己的解释器检查接口：

~~~powershell
& "./user-runtime/basic/Scripts/python.exe" "./resources/apps/xld-runtime-baseline/analysis-midi/runner.py" --engines
~~~

看到 basic-pitch 的 available 为 true 后再打开应用。界面 MIDI 工作流需要已有的基础分轨或整曲弦乐来源，安装转谱后端不会自动提供分轨模型。

### HiRes

适配代码 revision：7568dc7f78b625e40cf9776e2806d164006610e3；权重仓库 revision：b7bec65a2b860aca72856b0feef58b5df407b777。Python 需能导入 piano_transcription_inference、torchlibrosa、pretty_midi、mido、importlib_resources 和兼容的 PyTorch。

XLD_HIGHRES_MODELS 下放 note_F1=0.9677_pedal_F1=0.9186.pth（钢琴）和 filobass_20000_iterations.pth（贝斯）。文件大小和 SHA256 见 analysis-midi/models.json。退休 GAPS 不必下载。

### MuScriptor

先在对应 Hugging Face 模型页接受条款并用本人账号下载。代码固定 revision：7f213afecf23bd6a1b8672aa223690ee9807cefb。模型文件必须匹配随包 models.json 中 checkpoint 的 revision、大小和 SHA256。

~~~text
<XLD_MUSCRIPTOR_ROOT>/
  upstream/muscriptor/__init__.py   上游源码
  models/model.safetensors         Medium
  models/large/model.safetensors    Large（可选）
~~~

安装该 revision 的上游依赖，XLD_MUSCRIPTOR_PYTHON 指向能导入 torch、einops、safetensors、soundfile、pretty_midi、huggingface_hub 的解释器。自己的完整环境无需与 YourMT3 共用 Python。只装 Medium 时 Large 不可用。XLD 使用本地权重路径，不会替你完成授权。

### SW 与 Mega53

两者 Python 使用已适配的 bs-roformer-infer 0.1.6（代码 revision 90346ad4a4db7334f3378054a46adf7280b72f73）及相容 torch、torchaudio、soundfile、scipy、yaml、ml_collections；依照上游准备适合自己显卡的环境。

SW 的 XLD_ROFORMER_MODELS 下放 BS-Rofo-SW-Fixed.ckpt 与 BS-Rofo-SW-Fixed.yaml，哈希见 analysis-separation/models.json。

Mega53 从上游 v1.0.21 获取 ckpt 与 yaml，在 XLD_REFINE_ROFORMER_MODELS 下放文件及 manifest.json。manifest 的 models.mega.checkpoint 与 models.mega.config 各需 file、sha256 字段；根据自己下载的匹配版本记录，不修改已生成结果的模型身份。目标映射在 analysis-refine/profiles.json，53 项不等于互斥的 53 个声部。

### YourMT3+

从 Space 取得 revision 5e66c1ea173a8186e0d20432b841d3180cc015b5 的代码和所需 checkpoint。XLD_YOURMT3_ROOT 下包含 upstream/amt/src/model/ymt3.py；检查点放在 upstream/amt/logs/2024/mc13_256_g4_all_v7_mt3f_sqr_rms_moe_wf4_n8k2_silu_rope_rp_b36_nops/checkpoints/last.ckpt。对应 Python 安装上游依赖，版本与校验以 analysis-midi/models.json 及 yourmt3.py 为准。

### ADTOF、AudioSep、段落与和弦

这些高级后端仍需人工配置，未提供通用的一键安装步骤。ADTOF 的外部 vendor 源码与权重不在界面包内；如自行取得适用授权，适配器期望 analysis-midi/vendor/adtof_pytorch 下的代码与 data/adtof_frame_rnn_pytorch_weights.pth（版本见 models.json）。AudioSep 还需要与本适配器匹配的 separator.pt、conditions.npz、manifest.json，不能仅指定原始大 checkpoint。

段落/和弦需要 XLD_RUNTIME_ROOT / XLD_STABLE_RUNTIME_ROOT 指向配套 analysis、analysis-ai、analysis-harmony runner 目录，同时配置 XLD_PYTHON、XLD_AI_PYTHON、XLD_HARMONY_PYTHON；这些旧后端的完整安装尚未整理成第三方可复现流程。本界面版不承诺照一条命令就能启用所有引擎。不需要这些功能时保持未配置即可。

## 失败排查

- 不可用：核对选中的模型、解释器是否存在、依赖是否装在这个解释器里、权重路径和版本是否正确。
- 哈希失败：下载未完成或版本不匹配；按清单重新获取，不关闭校验。
- 显存不足：先试短片段或较小模型；CPU 支持因后端而异，当前 ADTOF/PyTorch CPU 路径有已知兼容问题。
- 全局诊断报其他模型缺失：允许部分安装，优先看自己配置的卡片和目标任务结果。
- 提交反馈时不要上传 HF/GitHub token、个人音乐或整套模型。
