开始使用MIDI细分文件管理搬迁与升级排查问题

第一次使用

  1. 打开 XLD.exe，点击“更换曲库”，选择自己的音乐目录。单击曲目进入工作台，双击播放。
  2. 在“资料库”中更改分析资料库，选择有足够空间的输出目录。首次默认曲库是 Windows 音乐文件夹，分析结果默认位于文档下的 Xin Music Lab/Analysis。
  3. 进入“分轨”，用默认模型生成 WAV 并试听。已有有效结果可以复用。
  4. 进入“MIDI”，选择声部、模型后生成，或点击“一键生成 MIDI”。目录按钮用于取得各次结果。
  5. 段落、和弦分别在对应工作台运行；XML 读取 XLD 的已有结果，负责播放与可视化。
预览版使用独立偏好，不会自动带入开发者的曲库和实验目录。原有曲库与输出不会移动或删除；想继续使用时，在预览版重新选择这两个目录。

MIDI 与一键生成

声部默认与备选
pianoTranskun V2（预测力度与延音踏板）；HiRes 备选。
bassHiRes；备选以模型菜单为准。
guitarMuScriptor Medium；复杂曲可比较 Large。
strings（可选）MuScriptor Large；Medium、YourMT3+、Basic Pitch 备选。
drumsADTOF（5 类，固定力度）；备选 ADTOF · DrumSep 7 类（drums.1 起：同一套鼓点，crash / ride 由鼓组分离判定，力度为本曲内相对能量）、MuScriptor Medium / Large。

一键生成依次处理 bass、piano、guitar、drums，以及你选择加入的 strings，使用各声部菜单中选定的模型。有音符的声部至少两个时生成融合 MIDI，单声部与融合结果分别保存。可在 FL Studio 等软件中导入并调整音源。

默认复用当前来源、模型和版本的有效结果。“重新生成”只重算本次 MIDI。取消或失败会停止余下步骤，已完成文件保留，再次执行可复用。

加入弦乐与理解音质

先完成 Mega53 整曲弦乐提取，再在 MIDI 页选择一份弦乐音源。30 秒预览不进入整曲 MIDI。弦乐组与小提琴等子声部一次选择一项，避免重复叠加。“不加入弦乐”仅改变本次计划，不删除历史文件。

转谱是离散音符的近似，连续揉弦、滑音、失真、电子采样和鼓奏法可能简化。当前接入的弦乐模型采用固定力度；ADTOF 输出五类鼓点。MIDI 的最终声音还取决于你加载的乐器音源。

模型版本与历史结果

每次转谱记录模型版本。旧结果可以打开、试听及参与融合，升级模型后不作为新版缓存复用；删除一次运行不影响其他版本或共用 WAV。

同一模型的多个版本在 MIDI 页「模型版本」里管理（默认折叠）。每行可切换（切到哪一版就用哪一版，不重新推理）、保留、删除或打开目录。切换后时间轴与融合都按新选择读取。

生成新版本后会自动回收盈余，只保留当前版本、最近一次对照，以及你标记保留的版本。只回收没有任何指针指向的版本，正在使用的那一版不会被删除；与当前版本完全重复的直接删除，其余移入回收站，可恢复。音源已变、文件已删除、记录损坏三类永远不会被自动回收。标记保留的版本永久保留，同时会一直占住它所依赖的 WAV 分轨。

切回旧版本之后，「生成 MIDI」仍然会用当前模型版本重新转谱；若只想回到当前版本而不重新推理，在「模型版本」里按「切换」。一键生成同样会把回退过的声部重新生成。

和弦引擎

引擎用途
ChordMini · BTC-CL主引擎（chords.2 起）：与 BTC 同架构、同 170 类词表的蒸馏版；专辑批量、和弦页默认选中与 XML 加权共识都以它为主。
BTC · Transformer备选与对照基准；已有 BTC 结果继续可读，XML 里可单选。与 ChordMini 的差异多在 maj7 / 7 与转换点。
consonance-ACE · Conformer按根音 / 低音 / 音级分解输出，保留转位（如 Bb7/3）与 6、maj7 等扩展；对乐句起止较敏感。
Librosa CQT / CENS / Hybrid轻量模板方法，CPU 可用，作快速参考。

三种神经引擎都需要显卡；同一曲目可分别运行后在时间线上对照。原始词表标签保存在结果的 rawLabel 字段，界面显示的是统一后的简写。

Mega53 细分

在“分轨 → 细分”选择 Mega53，可从原曲直接提取，也可使用已有 other、guitar 等声部。按乐器分类选择目标，先试 30 秒预览，再决定是否处理整曲。Bowed 与 AudioSep 保留为预览备选。

53 项是可提取的目标，不是 53 条互斥音轨。单次目标与剩余对应当前输入；不要把目标、剩余和原输入同时相加，也不要直接叠加独立提取的重叠目标。整曲弦乐可手动加入 MIDI，其他细分目标尚不自动加入一键计划。

输出与设备

original.wav、target.wav、residual.wav 保存原始 FLOAT 输出；listen- 前缀文件用于试听。显存不足时先缩短分块，再尝试 CPU，速度会下降。模型、目标、输入及范围分别缓存。

寻找与清理文件

入口内容
WAV 目录当前分轨来源的音频。
本曲 MIDI 目录本曲各声部和融合的历史输出。
声部 MIDI 目录当前音源、当前模型的有效结果。

按钮灰色时，确认当前歌曲、音源和模型已生成结果，再点刷新。切换分轨来源后会显示对应 MIDI，历史文件仍保留。本曲目录不受“原曲”试听选项影响。

不满意的 MIDI 可从 MIDI 页删除，核对运行与模型后移至回收站。生成 WAV 在“资料库 → 存储管理”中按体积检查，满意结果先标为“保留”。存在依赖或正在使用的音频受到保护。

回收站与恢复

默认移至回收站，清空回收站后才释放空间；永久删除需再次核对。WAV 清理以一次输出为单位，不删除原曲、模型、MIDI、段落或人工标注。移除后索引仍可识别缺失状态；未被新结果替换时，可从回收站恢复原目录。当前资料库之外的开发缓存不会被扫描。

路径、搬迁与升级

运行环境路径以 runtime.json 所在目录为基准保存。先关闭两个程序，再一起搬迁以下目录并保留结构：

Xin-Music-Lab/
  releases/{{VERSION}}/
    XLD.exe、XML.exe、runtime.json、resources/…
  runtime/
    0.5.0/…
    addons/…

不能只复制 EXE 或只复制 releases。MuScriptor 与 YourMT3 当前共享 Python，保留完整 addons。模型缓存需要可写目录。

曲库与分析资料库是用户选择的位置，仍保存绝对路径，不随程序搬迁。换盘或换电脑后，通过界面重新选择对应目录；不会自动搬走音乐和结果。预览版后续版本共用预览偏好；常规版、开发版偏好与其隔离。

升级使用新版本完整目录并保留旧版，需要回退时关闭新版，再启动旧版。不要同时让两个版本处理同一资料库。此包依赖配套运行环境，尚不是通用安装包。

遇到问题

运行随包“检查环境.cmd”，检查段落、和弦、分轨、细分及已配置 MIDI 引擎。它不生成歌曲、不评价音质。每项最多两分钟，可按 Ctrl+C 停止。报告保存在 %LOCALAPPDATA%/XinMusicDiagnostics/，包含本机路径，分享前请检查。

反馈时提供版本、Windows 与显卡、模型名称、失败步骤和任务提示。环境就绪不等于完整功能已在你的机器上验证。首次试用建议用自己的短音频验证播放、分轨、MIDI、目录、取消重试与重启恢复。

当前为本机验证的开发预览；无开发环境 Windows、不同显卡以及第三方组件再分发核对仍待完成，暂未提供公开通用下载包。

Quick reference

XLD analyzes music; XML visualizes its results. Choose your library and analysis folder, separate stems, then generate MIDI. The batch includes bass, piano, guitar, drums and an optional full-song strings source. Keep releases and runtime together when moving the software. User-selected music and output folders stay where you chose them. Preview profiles are separate; clean-machine acceptance is pending.
