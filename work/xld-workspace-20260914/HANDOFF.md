# XLD 工作台整合 · 第一轮

日期：2026-09-14。开发版：XLD `0.5.0-dev.core.6`；XML 继续为 `0.5.0-dev.stems.7`。

## 设计决定

以歌曲和操作组织工作台。用户明确选择“工作台默认，曲库作为侧栏”。左侧浏览专辑和曲目；右侧默认进入歌曲概览，随后切换段落、和弦、分轨或 MIDI。切换工作区复用已有状态和控件，不创建新的分析服务。

| 入口 | 提供的操作 |
|---|---|
| 曲库侧栏 | 搜索、专辑/曲目切换、选择歌曲、播放专辑、随机播放、整张专辑串行分析 |
| 概览 | 当前歌曲的段落/和弦结果数、有效 WAV 数、已有 MIDI 的声部数、人工标签数、刷新结果、更新 XML 接口 |
| 段落 | 展开选择模型、单模型或四种 MSAF 分析、SongFormer 长曲分段、时间轴比较、人工标签、结果管理 |
| 和弦 | 展开选择 CQT/CENS/Hybrid/BTC、四模型串行运行、可选伴奏预处理、时间轴、结果管理 |
| 分轨 | BS-RoFormer SW 默认、Demucs 6s 备选、生成/激活、音源试听、WAV 目录 |
| MIDI | 共用 WAV 音源选择，按 bass/piano/guitar 显示默认/备选模型，生成/激活、MIDI 目录 |
| 常驻区域 | 工作歌曲标题、当前任务及取消、底部播放器 |
| 次级区域 | 顶部资料库路径与更换，工作区底部任务日志，段落/和弦结果管理 |

模型列表不再与所有功能一起堆叠。段落和和弦将模型选项收进可展开区域，时间轴得到更多空间。分轨和 MIDI 保留直接可见的默认/备选卡片。

## 状态和接口边界

- 浏览其他专辑不清空工作歌曲；“定位曲目”回到工作歌曲所在专辑。
- 工作歌曲、播放歌曲、任务歌曲独立。选曲不自动播放，切换页签不取消任务；重新打开默认概览并恢复上次选曲。
- 任务卡不随工作区滚动；完成、失败、取消状态保留到手动收起或下一项任务。提交阶段不可取消时禁用按钮。
- 概览以已有结果汇总，不将未跑模型判成失败，也不要求跑齐所有模型。长曲部分覆盖单独提示；人工标签不计入机器分析份数。
- 分轨卡片只预选；生成/使用成功才切换有效 WAV。MIDI 继续跟随对应 sourceRunId，模型独立缓存。浏览页面不激活模型。
- XLD 仍拥有执行器和结果管理，XML 消费原有接口。音频、机器结果、人工标签保存方式和模型推理代码不变。
- 曲库变更后，已不存在的工作歌曲会清空；刷新期间保留仍存在的工作歌曲。

## 文件地图

- `source/xld-runtime-baseline/index.html`：两栏结构、五个工作区入口、常驻任务位置。
- `workspace-controls.js`：页签、侧栏层级、真实结果概览、键盘导航。
- `workspace.css`：工作台布局和桌面窄窗口适配。
- `app.js`：连接选曲/结果/任务状态；恢复选曲、滚动位置与上下文计数。
- `derived-controls.js`：向工作台提供只读快照，按分轨/MIDI 页面显示结果与失败信息。
- `i18n/catalogs.js`、`i18n/runtime-messages.js`：中英双语；修正和弦模型数量及长曲操作位置文案。
- `tests/workspace-summary.cjs`、`tests/workspace-ui-electron.cjs`：部分覆盖判断与真实窗口交互验收。

- XLD `npm test` 通过：界面语法、本地化、共享读取器、任务互斥、取消、MIDI 缓存、模型结果隔离与人工标签等。
