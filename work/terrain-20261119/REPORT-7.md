## 2. 加载
- 新模块 `score-terrain-assets.js`（全局 `XinScoreTerrainAssets`）：按清单预加载、解码全部 101 张，再做派生层（见第 3 节 E），全部做完才算就绪；任何一张失败就整体失败。
- `score-terrain.js` 在每次 draw() 开头只判一次：全部就绪就整帧用图，否则整帧用原来的代码画法。原来的画法函数一个都没删，作后备。**不会半图半代码。** 所有缓存了画好像素的地方（栅格、精灵、山的分块、站的精灵）键里都带了画法，所以切换之后的帧和「一开始就加载好」的帧一样。
- 宿主：
  - presentation 的 `ready()` 在这一款下等素材；
  - 导出页在导第一帧之前等 `ready()`。查过：terrain.7 导出的视频第 0.02 秒那帧已经是图（`batch7/export/frame-0.02.png`）。
  - XML 切到这一款或打开歌时，等素材最多 2 秒，期间保持上一帧，和雷达一样（`WAIT_LOOKS`）。
- Node 测试环境里没有 Image，状态是 'none'，走代码画法，原有测试照旧有效。新增测试 `terrain-assets.test.cjs`（101 张、哈希、8 MB、Node 下走代码），XML 的 `score-radar-wait.cjs` 加了车窗地貌这一条。

**E 叠加纹理**（`05`、`12`）
- 山体笔触：最近一两重用最粗的 a，往远 b、c、d。岩层纹替代代码原来近山上的五道横线。两者都**画进山的分块里**，按每重山的世界坐标对齐（每重山一个相位），跟着山走，不浮在屏幕上。
- 混合方式：分块是透明的、底下没有颜色，没法直接用柔光。所以把灰纹理先做成「白 / 黑 + 透明度 = |2s−1|」的一层，在 .45（岩层 .5）的强度下用普通叠加。效果近似柔光，不会像正片叠底那样整体压暗：七里香 1:44 山的区域平均变化 6/255。这个做法是我定的。
- 天空纸纹：天空栅格本身不透明，所以真用的 `soft-light`。
- 雾带：雾带图按原规则染色（basinAt 600，带封面取色）、原来的强度，沿前一重山软化后的山脊一片片铺。只铺雾带图里有内容的那几行（24–74%），每三个世界采样一片。
- 玻璃：大块玻璃贴斜阳光斑 a，上面小块贴 b（原来的冷色调保留），整块玻璃贴浮尘 b，都用素材原始透明度（`STREAK_K = DUST_K = 1`）。

## 5. 同一时刻同样的像素（`batch7/same-pixels.cjs`，照第 5 批的做法）
- 同一刻有三种画到的方式：直接画；连续播放 3 秒画到这一刻；先跳到别处再跳回来。
- 素材有两种到的方式：第一帧之前就绪；先用代码画三帧、素材到了以后再画。
- 结果：**七里香 1:44.4、choke 12:21.2，六张 PNG 逐字节相同**（七里香 `a3f77dbe…`，choke `8e8174bb…`）。代码画法单独跑也通过。
- 中途查出过一个问题，已修（7.7）：玻璃边那一行是半透明的，会透出上一帧，差 1–2 个色阶。代码画的窗框描边原来正好盖住这一行，换成窗框图以后露出来了。
