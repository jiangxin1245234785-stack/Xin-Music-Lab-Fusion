## 1. 卡顿
### 先量的结果（改之前，terrain.1）
- 真窗口：七里香 draw() 每帧只要 4.7 ms，但帧间隔 44.8 ms。**慢的不是脚本，是 GPU 画像素。**任务书的「draw 平均 ≤ 5 ms」这条，terrain.1 其实已经满足，但照样卡，所以下面两种数都报：draw() 的耗时和实际帧间隔。
- 测速页里逐项关掉看帧间隔（1440×778，DPR 2，屏幕 120 Hz，最快 8.3 ms 一帧）：

| 关掉的部分 | 帧间隔 ms |
|---|---|
| 什么都不关 | 58.5 |
| 只关山 | 26.4 |
| 只关山之间的雾带 | 40.2 |
| 关山 + 雾带 | 8.4 |
| 只关裁剪（每重山、每条雾带都按山形裁一次） | 45.4 |
| 天、云、地面、路边、玻璃、颗粒、车厢 | 每项 ≤ 2 |

  结论：几乎全部时间花在每帧重画 8 重山：按山形裁剪（约 15 ms）、雾带（约 10 ms）、阴面 / 阳面、岩层线、山脊线、山脚的雾。
- 读码的怀疑（任务书里的）基本对：`paintRange` 每帧重建路径、裁剪、给每个峰新建渐变、逐列画山脚雾。

### 改法（`score-terrain.js`）
- 一重山的样子拆成两部分：
  - **世界形状**：只由这一轨自己的响度和音符决定、站在固定山脚上的山形。它和时间无关。
  - **偏移**：被前面的山垫高的台阶、为了露出来往上抬的量。它随时间变（每帧最多约 1.3 个草图像素），所以整重山不能做成一张图只平移。
- 阴面、阳面、岩层线、山脊线、山脚雾，以及「这重山铺在后面那重山上的雾带」，按世界形状每 256 个采样画成一块图，存起来（总像素上限 6400 万，超了丢最久没用的）。
- 每帧：山体本身仍按这一帧的真实山脊填色（轮廓一点不变）；然后把块按「这一帧山脊 − 世界山脊」的偏移贴上去。偏移按分段直线走，每段斜着贴（剪切），段与段在整像素上对齐、不重叠（第一版有 1 像素重叠，阴面被画两遍，出现过细竖线，已修）。一帧大约贴 200 段。
- 雾带不再按山形裁剪：先把所有山画进一张透明的合成图，雾用 source-atop 只落在已有的山上，最后整张贴上窗口。
- 山体渐变的顶端原来取「窗里最高的那个峰」，高峰一进一出整重山的明暗就跳；改成「平均山脚 + 这重山的满高度」，不再跳。
- 没有离屏画布（Node 测试）时还按老办法整画。

## 2. 山的阴面闪
- 复现方法（`batch5/flicker.cjs`）：一次只画一重山（不画雾、云、地面、颗粒、玻璃），连续 60 帧，每帧步长取「这重山正好平移整数个像素」（约 1/60 秒），把下一帧和挪回去的上一帧逐像素比，数变化超过 24 和超过 8 的像素。
- 原因，读码 + 量：
  1. **阴面每帧重新挑**：峰在滑动的窗口里找，每个峰的阴面伸到「下一个峰之间最低的那点」，下一个峰在窗外时就伸到窗边，窗口一挪，阴面的形状就跳。量到的跳变：七里香 1:40 吉他那重，一帧之间最多 12866 个像素变化超过 24（平时约 700）。**改后（阴面按世界形状画在块上）同一处最多 345。**
  2. **渐变顶端跟着窗里最高的峰跳**：改成固定的，见上。
  3. **山随音乐升降**：台阶和抬升每帧在动（吉他、人声那几重，一帧最多约 3 个设备像素）。这一层在新旧两版里一样（变化超过 8 的像素：新旧平均都在 8000–16000 之间，差不到 10%）。按设计它是「升起和沉下」，没改。
- 修好的标准「同一座峰从进窗到出窗，阴面的形状和明暗除了平移不变」：现在阴面画在块上，形状和明暗确实不变，只随偏移整体上下挪。要是用户说的「一直在闪」其实是第 3 层（整片山在微微上下动），那要另外定「升降要不要更慢」，这不是我能定的。
- 两段 60 帧/秒的连续画面就是给这个判断用的。

## 3. 顶屏重排
- 第一行：左边歌名（最亮），隔一格歌手（中亮），右边「0:20 / 5:04」。没有「本站 ××」「下一站 ××」这几个字了。
- 歌手为空、或者是标签里的占位词（Unknown Artist、未知艺术家等），而歌名形如「周杰伦 - 七里香」：拆成歌名「七里香」+ 歌手「周杰伦」。歌手是真名字时不拆（例如「Hey - Jude」配 The Beatles）。
- 放不下：歌名 + 歌手当成一整条，按歌曲时间来回滚，一次一个整字，两头各停一会儿；不出现省略号。周期是 max(8 秒, 字数 × 0.6 秒)。
- 第二行线路条，现在分四档亮度：
  - 过了的站：暗亮；
  - 本站：最亮、常亮、带方框；
  - 下一站：站名中亮，站灯在每个歌曲秒的前半秒亮、后半秒灭（暂停时停在当时的样子）；
  - 更后面的站：最暗。
  - 线：走过的亮，没走的暗（原有的，保留）。
- 没有段落的歌：第二行全暗，不变。
- **准备状态字**（「正在准备人声线…」「这次没准备成…」）：车窗地貌下不再画在画布顶上（原来正好压在顶屏中间），改成画在左下车厢壁上、窗台歌词条左边，11 像素、暗灰；准备失败那种「可以点一下重试」的还是浅琥珀色，点的区域跟着挪了。改在 XML 的 `score-scene.js` 里，只对这一款生效。
- 模块里亮度从三档改成四档；窗台歌词和「现在」箭头用最亮那档，样子不变。

## 没验证的
- **没听声音**（静音启动），没试真的双击。
- 真窗口的计时是在 XML 的离屏测试窗口里量的，和真双击打开的可见窗口可能不同（显示器刷新率、合成方式）。choke 那约 20 ms 的下限是谁造成的没查。
- 真窗口第二次计时本想「收起侧栏」，脚本点了按钮但画布还是 1123 宽，**实际没收起**。所以真窗口里只有侧栏展开和沉浸全屏两种尺寸。收起侧栏的数只有测速页里的。
- 测速页里「打开七里香后第一次拖动约 800 ms」新旧都有，没查原因，真窗口里没出现。
- 闪烁第 3 层（整片山随音乐微微升降）是否就是用户说的「闪」，没法从数字判断，要用户看连续画面。
- 雾带现在铺在所有更远的山上，原来只铺在紧后面那一重上。紧后面那重不在而更远的那重在时，那里会多出一点雾。没出图对比。
- 山脚雾、岩层线是跟着「山脊的偏移」挪的；原来跟着「山脚」。被抬升的远山，这两样会比原来高一点（远山的山脚大多被前面的山挡住）。没出图对比。
- 块的显存占用没量（上限按像素算，约 256 MB）。
