# 车窗地貌 · 第 7 批任务书（接入 GPT 画的素材）· 2026-11-20

先读：`SETTING.md`、`SPEC-TERRAIN.md` 第一节的规矩、`REPORT-5.md`（山是分块预画的）、`REPORT-6.md`（过站、车窗、鸟现在怎么画的）、`gpt-assets/BRIEF-ASSETS.md`、`BRIEF-ASSETS-2.md`、`gpt-assets/out/NOTES.md` 和 `manifest.json`（锚点、轮毂、灯芯坐标、混合方式都在里面）。看 `gpt-assets/out/window-proof.jpg`：那是目标的样子。

## 背景
用户让 GPT 把这一款所有能换的东西画成了一套透明底手绘素材（101 张，`work/terrain-20261119/gpt-assets/out/`），用户看过说可以，主持会话验收通过。现在程序里这些东西是用 canvas 代码画的。本批把代码画的换成这套图，逻辑（什么时刻出现什么、让路、数量、遮挡规则）一律不变。

## 规矩（重申要紧的）
- 入口是 `releases/0.5.0-dev.terrain.4` 或更新的，**用户可能正开着**：不碰不关他的窗口。不切入口、不推送、不删 `releases/` 下任何东西。真实分析目录只读。
- 只有你一个人写 `source/scoreview/score-terrain.js` 和新增的素材文件；动手前 `git status`，有别人未提交的改动就停下来报。只提交自己改的；不 stash、不 reset、不切分支。
- 画面是歌曲时间的确定函数；同一时刻从播放、拖动、导出画出来逐像素一致。**图片是异步加载的**：没加载完之前怎么画要有确定的说法（见下），加载完之后必须和「一开始就加载好」逐像素相同。
- 帧耗时不许比 terrain.5 重（真窗口和测速页都量，对照 `REPORT-6.md`）；另量显存 / 位图内存和包体积。
- `gpt-assets/out/` 是 GPT 的原件，**不改它**；处理后的文件另放。素材本身有毛病不要自己修图，记进 `gpt-assets/REVISIONS.md`（给 GPT 的修改单，用户转交）。
- 三套 `npm test` 绿。脚本用写文件的办法。不下载东西（缩图、转格式用本机已有的工具：Electron / Chromium 的 canvas 就能做）。

## 要做的
### 1. 素材进仓库
- 原件 44 MB，不能原样进包。按实际最大显示尺寸（沉浸 2560×1600、DPR 2 时的像素）缩到够用为止，转成体积小的格式（WebP 带透明，或 PNG），放 `source/scoreview/assets/terrain/`，目录结构和命名照原件。写一个可重复跑的转换脚本放 `source/release-tools/` 或 `work/terrain-20261119/batch7/`，并记下每张的缩放倍数。**目标：整套进包不超过 8 MB**；做不到报数字。
- 打包清单（`source/release-tools/build-local.cjs`）、XML 和导出页的加载都要带上；包检查加一条「素材齐全、哈希对得上」。

### 2. 加载
- 一个小的素材模块：按清单预加载并解码，全部就绪后才用图；没就绪时这一款整体用现在的代码画法（现有函数保留作后备），**不许半图半代码地混着**。就绪后切换那一下允许画面变一次。
- 导出页必须等素材就绪再开始导第一帧。
- Node 测试环境没有图片：走后备画法，现有测试继续有意义。

### 3. 换上去（每类一笔提交）
- **A 铁路边**：电线杆（4 + 矮杆 2）、里程桩、鸣笛标、围栏桩（含带撑的）、石堆、蒿草、风车（塔 + 单独转的叶轮，轮毂坐标在 NOTES 里）、鸟（六帧循环，按歌曲时间选帧）。变体按「这是这首歌的第几个这种东西」的哈希确定地选。运动模糊、地上的影子、电线和铁丝仍由程序画；预画进精灵缓存的做法照旧。
- **B 过站**：站牌 3 种 + 站灯和光晕；小镇用水塔、粮仓、矮房、树、小站房、道口叉牌（左右灯交替按歌曲时间）、栏杆来拼现有的四种变体。**小镇的大小重定**：第 6 批压得太小太淡，真窗口里像几粒灰点，变体 3 还被路边的东西挡住了。改成：水塔 / 粮仓的高度 = 它身后最近那重山在交界那一刻高度的 0.8 倍，封顶 150 草图像素、最低 60；雾只混三成；小镇所在那段路上，路边的石堆、蒿草、里程桩也让开（电线杆不让）。
- **C 车厢**：窗帘左右（各 2 种，用哪种固定选 a）、轨道、横档、窗框转角、壁板、窗台、两块 LED 外框。遮挡规则不变（合计 ≤ 12%、不挡 37% 线、横档不压山），换图后重新数一遍面积。
- **D 天和地**：云带、平原、路基、另一条铁轨。平原换图要保住远近的雾和封面取色；路基和铁轨贴在窗下沿，按最近一层的速度平移（它们是「贴车的地面流线」，用户还没专门定过这条：做成一个内部开关，默认开，报告里单独出图让用户看）。
- **E 叠加纹理**：山体笔触（a 近 → d 远）、岩层纹、天空纸纹用**柔光**叠（NOTES 里说了正片叠底会压暗一半）；纹理要跟着山的世界坐标走（画进分块里），不许浮在屏幕上不动。最粗的 a 只用在最近一两重。雾带换成素材并按原规则染色。玻璃浮尘和斜阳光斑贴在玻璃上，强度做成常量，默认用素材原始透明度。
- 每一类换完，同一帧出「代码画的 / 换图后」对照。

### 4. 打包、真启动、交付
- 从干净镜像打下一个没用过的 `0.5.0-dev.terrain.N`（查 `releases/` 和 `%APPDATA%/XinMusicDevelopment`），隔离真启动，包检查保留雷达那条。**不切入口。**
- `work/terrain-20261119/phone-7/`（宽 1080，黄字标题）：五类各一张改前改后；整窗三张（七里香 1:44 普通窗口、沉浸、一首山最高的歌）；四种小镇各在交界那一刻；站牌过站四格；路基和铁轨开 / 关对照；叠加纹理开 / 关对照（放大到能看清笔触）；鸟飞起来的连续六帧；**真窗口连续画面两段各 10 秒 60 帧/秒不丢帧**（一段含小镇过站，一段是鼓密的歌）。
- `REPORT-7.md`：每类的做法、帧耗时和内存和包体积的对照数字、没验证的、你自己定的、最可能露馅的地方；三套测试尾部原样贴。
- `gpt-assets/REVISIONS.md`：放进真画面后发现的素材毛病，一条一条写清「哪张、什么毛病、想要什么样」，附对应的截图路径。没有就写没有。

## 不要自己定的
山的造型、配色、光线；鼓太密怎么减；玻璃上的车内反光、座椅、小桌板；素材本身的修改（写修改单，不自己修图）。
