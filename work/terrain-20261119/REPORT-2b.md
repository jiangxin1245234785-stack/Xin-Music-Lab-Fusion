## 怎么接的
- `draw` 的最后调用 `XinScoreTerrainLed`（全局，有就画，没有就跳过）：
  - 顶屏 `drawHeader(ctx, layout.header, {title, artist, sections, time, duration})`。
  - 窗台 `drawLyric(ctx, layout.sill, {line, progress})`。
  - 箭头 `drawNowTick(ctx, nowX, 窗上沿, 窗下沿, {pitch: 3u})`。
- 段落名取歌曲自己的 `sections` 行（bundle 里本来就是中文），英文名才过模块的 `localizeSection` 兜底。**没用 `frame.section`**：presentation 给的是已经翻成英文的段落名（它的 `sectionLabel`）。
- 歌词取 `frame.lyric`（presentation 现在给的是当前这句的文字）。XML 在引子、间奏、尾奏里本来就不给歌词，所以那时窗台不亮。
- 滚动进度：frame 里有 `lyricProgress` 就用它；现在 presentation 不给（它不知道这句什么时候开始和结束），所以先用「按歌曲时间来回扫」代替，周期 max(6 s, 字数 × 0.45 s)。这是歌曲时间的确定函数，但和这句实际唱到哪里没有关系。第 4 批在 frame 里补上 `lyricProgress` 就会按唱的位置滚。
- 热身：每首歌第一帧把歌名、歌手、所有段落名（连同缩写）、数字等字形一次采样完，之后换段落、换时间都不用再采样。

## 模块里改了什么
1. 顶屏拆成三块缓存：
   - 不含「时间数字」和「当前站往后那段线路」的静态条：换站、换歌名、换尺寸时才重建。
   - 时间数字：每秒一块小画布，只画亮点。
   - 当前站往后的线路：亮的那一头每挪一个灯点重建一次。
   - 两块小画布用 lighter 叠在静态条的熄灭灯点上，结果和整块画一样。
2. 歌词滚动的偏移只停在字与字的边界上（取最接近的字界）；滚到最后时取第一个能露出最后一个字的字界。两头放不下的字整个不画。
3. 没有段落：不画线路条那一行。
4. 新导出 `warm(字符串列表)`。

LED 单独量（Electron，每秒 30 帧、连续 6 秒，`render-1/page.html` 的 `ledTiming`）：

| 歌 / 尺寸 | 每秒那一帧 平均 / 最大 | 其它帧 平均 / 最大 | 冷启动第一帧 |
|---|---|---|---|
| 七里香 1123 | 0.27 / 0.4 ms | 0.03 / 0.8 ms | 18.2 ms |
| 七里香 1440 | 0.43 / 1.4 ms | 0.02 / 0.6 ms | 19.5 ms |
| MEGURI 1123 | 0.27 / 0.3 ms | 0.01 / 0.3 ms | 18.7 ms |
| MEGURI 1440 | 0.25 / 0.3 ms | 0.02 / 1.5 ms | 18.7 ms |

- 冷启动约 18 ms，热身之后也还是约 18 ms：大头不是字形（热身只花 2–3 ms），而是第一次把整块屏的熄灭灯点铺成底图（几千个灯点）。这一块按屏的尺寸缓存，换段落时不再重铺，所以只在载入歌曲或改窗口大小的第一帧出现。没有把它挪到「载入时离屏先画一帧」：因为第一帧本来就发生在载入时，挪了也是同一时刻的同样开销。
- 「其它帧」偶尔 0.6–1.5 ms：是线路条亮点挪了一格，或者换站那一帧；没逐个分开。

## 最可能露馅的帧
- 歌词刚换句的那一帧：歌词滚动没有这句的起止时间，长句可能从中间某个位置开始显示（来回扫的相位和换句无关）。
- 一首歌里第一次出现的歌词字：字形要现采样，每个新字约 0.2–0.3 ms，一句十几个生字的那一帧可能多出 3–5 ms。没量。
