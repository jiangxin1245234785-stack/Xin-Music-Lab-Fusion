## 2. 鸟减少
- 吊镲的鸟群：5–8 只 → **2–3 只**。叮叮镲：3–7 只 → **1 只**，一串里每下离上一下不到 2 秒的算同一串，只在第一下飞 1 只。同一时刻窗里最多 8 只：按歌里的先后顺序、按每群鸟自己飞出窗顶要的时间算，超了的那群只画剩下的名额（不会半路冒出来）。「只留底鼓和军鼓」那档没动。
- 数字（`batch6/census6.json`，曲库 32 首有 levels 的歌全扫）：新规则下**全曲库任何时刻窗里最多 4 只**，8 只的上限从来没碰到过（是个保险）。
- 曲库叮叮镲最密处：Plein Soleil 6:07.9 起 10 秒 65 下。图 `12-鸟-改前改后.jpg`：6:01.9 那一刻旧规则下天上约 53 只（按 2.7 秒飞行时间估的，图上能数出二三十只），新规则下 0 只——这首从 5:30.6 起叮叮镲连着敲了半分多钟，按「2 秒内连敲只算一次」整串只在 5:30.6 飞 1 只（下面两格是 5:31.2 那一只）。
- **请用户看**：「连着敲的一整串只算一下」在 Plein Soleil 这种整段铺叮叮镲的歌里，等于这一整段几乎没鸟。这是任务书的字面规则，我照做了；如果想要「每隔几秒还是飞一只」，要另定。

## 3. 车窗：细横档 + 束带窗帘

## 4. 过站
- **规则**（`stationsOf`）：线路屏在每段开始那一刻换站，窗外就在那一刻让一样东西正过「现在」线。
  - 进副歌、进间奏 / 器乐段 / 独奏（按段落的 kind；kind 没有或认不出时看名字，词表和窗台歌词判断「没人唱的段」那套一致）→ **小镇**；其余交界 → **站牌**。
  - 第一段起点、最后一段终点、头尾平原里、没有段落的歌：不过站。离上一个**画出来的**站不到 8 秒 → 降成站牌；不到 3 秒 → 不画。小镇离平原不到 3 秒也降成站牌（免得镇子出现在平原里）。
  - 过站属于线路：「路边的东西」三档（含「关」）都画。
- **站牌**：mock8 的 A：贴着铁路（比道床还近）两根柱子、一块蓝灰横牌、牌面一道模糊浅色条（没有字）、一盏鹅颈站灯；运动模糊是电线杆的 1.5 倍。在窗里 **1.4–1.6 秒**。
- **小镇**：mock8 的 C 改了三处：
  - 收窄：在窗里 **5.2–5.9 秒**（普通窗口），沉浸 4.6–5.2 秒，侧栏展开 4.2–4.8 秒（窄窗口看到的路程短，**侧栏展开时略少于 5 秒**，没为它单独调）。路不伸到近处：只有道口那种在铁路道床上画一截木板。
  - 压矮压暗：粮仓、水塔的高度 = 交界那一刻「现在」处最近一重高过 20 的山高度的一半（4 像素一档，最低 24、最高 110 草图像素）；房子和树不跟着缩（本来就矮于半山）。颜色先混进雾色一半、再往阴影色压 22%，比身后的山暗。画在空气雾之前，雾也盖在镇子上。
  - 四种：水塔 + 两栋房；粮仓 + 一栋房；道口 + 两栋房和树；水塔 + 粮仓、三栋房（大一点）。按「这首歌的第几个大段落」轮着选（降成站牌的大段落也占一个号），同一首歌每次一样。七里香的四个大段落正好轮完四种。
  - 交界那一刻，镇里最高的东西（水塔 / 粮仓 / 道口那种是中间那棵大树）正在「现在」线上；道口本身在交界后约 0.7 秒过线，红灯每半个歌曲秒换边。
- **让路**：小镇所在那段路上，远处那条线（风车、鸟群）让开；道口前后 4 米的里程桩 / 鸣笛桩让开。按「在铁路上的第几米」判断，跟着站一起走。电线杆照常。**电线和铁丝**：站牌比所有路边东西都近，线都在牌子后面，不会有线穿过牌子；小镇在围栏后面，围栏的铁丝在镇子前面，是真实的样子；道口没画通到镇子的路，所以也没有铁丝横穿路面的问题。
- 每种站都是按光线、尺寸、DPR 预画一次的位图（一首歌第一帧把要用的全画好），每帧只平移。
- **线路屏换站和过站是同一刻**：
  - 测速页 `09-线路屏换站和过站同一刻.jpg`：交界前一帧（相差 1/60 秒）本站灯还在上一站，交界那一帧灯跳到下一站，站牌正中 / 水塔正在箭头上。
  - 真窗口 `15-真窗口-…jpg`：同样。注意 XML 画面的时间 = 音频时间 − 0.070 秒（XML 自己的延迟补偿，每次都正好 0.070），所以拖到 0:56.282 时画的是 0:56.212；截图时我把这 0.070 补上了。灯和站用的是同一个画面时间，两者之间没有偏差。

## 5. 顶屏英文 + 里程
- 站名在这一款顶屏上一律英文大写：引子 INTRO、主歌 VERSE、导歌 PRE、副歌 CHORUS、间奏 BREAK、器乐段 INST、独奏 SOLO、桥段 BRIDGE、尾奏 OUTRO，序号保留（VERSE 1）；英文的段落名同样处理；认不出的原样（例如「过门」）。我多加了 前奏 → INTRO、尾声 → OUTRO 和几个繁体写法。歌名、歌手、窗台歌词不动；XML 别处和别的款不动。
- 排不下：先把序号前的词缩成三个字母（CHORUS 2 → CHO 2），再不行按原来的办法（首字母 + 序号……）。七里香在普通窗口全名放得下，侧栏展开时变成 VER 1 / CHO 1；Flowers（25 站）两种宽度都是 I1 V1 C1……，不挤，见 `13-顶屏英文-七里香.jpg`、`14-顶屏英文-段落最多.jpg`。
- 右上角改成里程：固定 79 英里/小时，「2.2 / 6.6 MI」（一位小数，都往下取，不会跑到车前面）。换算在 LED 模块里：常量 `TRAIN_MPH`、函数 `milesOf` / `readout`；模块默认仍是时间。**退回的开关**在 `score-terrain.js`：`HEADER_READOUT = 'time'` 回到「1:44 / 5:03」，`HEADER_NAMES = 'zh'` 回到中文站名。没加到 XML 设置里。
- 我自己的选择：里程往下取整（任务书例子里 5:04 写的是 6.7，按往下取是 6.6）。

|---|---|---|
| 七里香 1:30–2:00，侧栏展开 | 17.41 / 16.8 · 4.41 / 10.8 | 17.56 / 33.2 · 4.51 / 13.0 |

- 结论：真窗口里两者**基本持平**——draw 平均差在 ±0.15 ms 以内（沉浸时本批低 0.6 ms），帧间隔平均差在 ±1 ms 以内，只有 choke 那行本批高 1.1 ms、沉浸那行低 2.3 ms，在两次跑之间的波动范围内。七里香两行 p95 从 16.8 变成 33.2（也就是偶尔一帧占两个刷新的次数变多），平均几乎没变；是不是本批造成的，单次测量判断不了。

- **变重了的一项：新歌 / 新尺寸的第一帧**。测速页里打开一首歌的第一帧：七里香 106–143 ms → 172–257 ms，choke 39–101 → 31–53。多出来的是逐像素画窗帘（每换一次窗口尺寸画一次）和这首歌所有站的位图。真窗口里打开七里香的第一帧 draw 15.8 ms、choke 5 ms（位图在 draw 之外的别处已经建好，没细分）。拖动后出新帧 28–127 ms（和第 5 批的 30–126 ms 同一量级）。
