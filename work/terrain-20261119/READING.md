## 结论先行

- **它声称**：坐在车窗边看山。山高 = 全曲响度，山体一层层地层 = 各分轨此刻的响度占比，地层里刻着音符，下方小地图 = 全曲轮廓和车的位置。
- **它实际画**：山高和地层确实接了真数据（`energy.db`、`levels.groups`），而且随数据变。但：
  1. **地层没有名字**。`METALS` 里每层都有中文名（人声、弦乐……），代码注释也说「labelled geological band」，可画面上一个字都不写，也没有图例。只能靠颜色猜是哪件乐器 → 「MEGURI 4:02 指得出当前在响的乐器」现在做不到。
  2. **音符只画两条轨**：一条「主」（有人声就是人声，否则按 弦→管→键盘→吉他… 顺序挑一条 lane），一条「伴」（偏弦乐/贝斯）。七里香 11 条 lane 只上屏 2 条（人声 + 弦·小提琴），MEGURI 12 条只上屏 2 条（弦·大提琴 + 贝斯）。鼓、吉他、钢琴的音符永远不画。
  3. **音符画法 = 1.14 px 的奶白 / 淡蓝细线，外描 2.1 px 暗边**。透明度并不低（.97 / .93），淡是因为：线太细；和地层里本来就有的几十条装饰性「岩层纹」一个形状（都是顺着地层走的细横线）；主旋律的奶白 (255,234,192) 落在弦乐层的米黄 (#d9bc8d) 或人声层的粉 (#e2ada0) 上几乎同色。最显眼的反而是「伴」那一轨的淡蓝线落在最底下深色的贝斯层上 —— 这就是「只有几根白线」。
  4. **音高几乎看不出**：音的纵向位置 = 该乐器那一层的厚度里按音高插值（`voiceDepth`），层薄的时候整条旋律被压在几像素里（七里香 1:44 弦乐层只有 7 px 厚），线的斜度主要来自山坡，不来自旋律。
  5. **播放中没有播放线**。竖的播放线只在暂停/拖动时画（`locating`）；播放时「现在」只有下方小地图上的一根线。过去和未来的音长得一模一样，没有「正在响」的提示。
  6. 和弦、小节、节拍完全没接；段落名、歌名、封面、歌词只在 **沉浸模式**（或关掉「专辑侧栏」时）画进画面。
  7. 画面上方约 35–40% 永远是空天（山最高也只到 y≈263/783）。

| 中景山、远景山 | 同一份响度，分别 3.45 s 和 7.9 s 平滑（`formation` 361）——不是别的数据，只是更慢的同一条曲线 |
| 地层 | 每个分轨（vocals/strings/winds/piano/guitar/other/drums/bass）一层，从上到下按这个固定顺序；层厚 = 该分轨此刻功率 / 各分轨总功率（1.33 s 平滑） |
| 地层里刻的线 | 两条 lane 的 MIDI 音符（`localMidi` 708、`engravedMidi` 771） |
| 小地图（底部） | 全曲响度轮廓 + 当前窗口框 + 播放点三角（`journeyMap` 599） |
| 天空 | 固定渐变 + 固定纸纹，按「曲子」挑配色 |

## 音符怎么画（为什么「太淡，只有几根白线」）

- 选轨（`midiVoices` 626）：排除 texture，按家族顺序 `vocals, strings, winds, piano, guitar, other, bass, drums` 选**一条** lane 当主，同族里按最早出现、再按总时长；伴 = 另一族里按 `bass, strings, piano, winds, guitar, other, vocals`（主是人声时把 strings 提到最前）选**一条**。全曲固定不变。
  - 七里香：主 = 人声（726 音），伴 = 弦·小提琴（465 音）。
  - MEGURI：主 = 弦·大提琴（1128 音），伴 = 贝斯（896 音）。MEGURI 第一把失真吉他（2914 音，全曲最多）不上屏。
- 位置（`voiceDepth` 691）：音被放进**与它同族的那一层**里，按音高在该层上下 84%→16% 之间插值；族没有对应层时按固定比例放在山脊下方。
- 画法：每个音一条折线（每 1/6 s 一个点，顺着地层弯），先画 2.13 px 的 `rgba(22,28,30,.86)` 暗边，再画 1.14 px 的颜色线：主 `rgba(255,234,192,.97)`、伴 `rgba(177,214,218,.93)`；起点有一个 1.75–2.65 px 的小撇。
- 上屏数量（inspect 统计，见 `inspect.json`）：

| 帧 | 上屏音符 | 主 / 伴 | 该时刻实际在响的 lane |
|---|---|---|---|
| MEGURI 4:02 | 36 | 大提琴 20 / 贝斯 16 | 小提琴、弦·大提琴、弦·中提琴 |
| 七里香 1:44 | 120 | 人声 83 / 小提琴 37 | 电吉他、木吉他、钢琴、5 条弦、贝斯（人声此刻在两句之间） |
| 七里香 2:23 | 37 | 人声 14 / 小提琴 23 | 木吉他 |
| MEGURI 8:20 | 280 | 大提琴 167 / 贝斯 113 | 失真吉他、小提琴、4 条弦、鼓 |

- 层厚（播放点处，px）：七里香 1:44 人声 178 / 弦 7 / 钢琴 2 / 吉他 36 / 鼓 31 / 贝斯 77 → 小提琴的整段旋律挤在 7 px 里；MEGURI 4:02 弦 61 / 钢琴 0 / 吉他 11 / 鼓 7 / 贝斯 32。
- 所以：主旋律颜色贴近所在层的底色、形状贴近装饰纹，读起来像又一条岩层纹；伴奏的淡蓝在暗色贝斯层上才显出来，于是看到的就是「几根白线」。

## 选项

terrain 自己**一个专属选项都没有**。它只读 presentation 传进来的 frame：`w, h, song, key, time, duration, playing（= !locating）, section, lyric, cover, presentationLayout, albumLayout`。

XML（`source/fusion-runtime-baseline`）里用户能点到、且真的影响这一款的（已核实）：

| 用户点的 | 位置 | 对车窗地貌的作用 |
|---|---|---|
| 谱面样式 → 「车窗地貌」 | `index.html:262` `#scoreStyle`，`score-scene.js:190-197`，存 `xin-score-style-v1` | 选中这一款；`score-theme.css:5` 给侧栏配色 |
| 沉浸模式按钮 | `index.html:67` `#immersiveButton` → `app.js:3066` 加 `is-immersive` → `score-scene.js:460` 设 `presentationLayout` | 画面改成 720 高的逻辑尺寸；画歌名、歌手、封面、段落名（英文，如 "Chorus 1"）、歌词字幕 |
| 专辑侧栏开关 | `index.html:277` `#scoreAlbumLayout`（默认开）→ `score-layout.js` `score-layout-active` → `albumLayout` | 关掉时歌名/封面/段落名画进画面 |
| 同步「早/晚 10 ms」 | `score-scene.js:693-699` → `offsetSeconds` | 整个画面时间平移 |
| 暂停 / 拖动 | `score-scene.js:437` `draw(undefined, audio.paused \|\| audio.seeking)` | 才出现竖播放线 |
| 在画面上点 | presentation `hit` → terrain `timeAt` | 跳到点的时间（主窗口或小地图） |

不起作用的（terrain 不读）：分轨隐藏/聚焦、外观/明暗、形状、对比（只给星空/压纹纸）、雷达三项（只对 glass 显示）。`noteAt`（点中音符）写了，但 XML 的 `hit` 不调用它 → 音符点不中。

## 时间、随机、开销

- 没有 `Math.random` / `Date` / `performance.now`。纹理用固定种子 LCG，颗粒随歌曲时间平移，画面是歌曲时间的纯函数 ✔。唯一和「播放状态」有关的是播放线（暂停才画），这是有意的。
- 帧耗时（draw 的 CPU 时间，1123×783，每 0.25 s 一帧共 80 帧，`timing/jobs-out.json`）：
  - 七里香 95–115 s：均 5.5 ms，p99 8.4，最大 8.4，>8 ms 3 帧；
  - MEGURI 232–252 s：均 5.1 ms，p99 8.4；
  - MEGURI 490–510 s（最密）：均 6.4 ms，p99 10.8，>8 ms 6 帧。没有 >16 ms 的。
- 热点：每帧约 25 条（远/中景 2×13）+ 每层 10 条（7 纹 + 碎斑 2 + 边界 2）+ 山脊 2 条的折线，每条 ~433 点（24 s × 18 点/s）；整屏图案填充 2 次（颗粒）；一个 ~100 色标的横向渐变每帧重建；约 15 次 clip。音符本身不贵（280 个音 ≈ 1 ms 级）。
- 缓存：`source.world`（每 1/18 s 一个采样点）只增不删，全曲最多 ~1 万项，可忽略；天空层和小地图按尺寸缓存。
