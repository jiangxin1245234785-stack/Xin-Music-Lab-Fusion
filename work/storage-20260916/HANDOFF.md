# XLD 音频存储管理第一版

版本：XLD 0.5.0-dev.core.14，独立 releases/0.5.0-dev.storage1；XML 与模型不变。当前阶段：实现/测试/构建完成，发布结果见 published-checks.json。沿用旧开发分析目录，旧 mega2/RC.6 保留。

范围：资料库 → 存储管理。扫描当前分析根目录，统计文件逻辑体积和 WAV 体积；识别 album/track/stems|refinement/UUID 下的一次完整输出，按体积降序。显示歌曲/专辑、模型、目标、来源、范围、日期、保留/当前/依赖。支持搜索、类型过滤、选择可清理项、取消选择、逐项保留与取消、打开目录、回收站或永久删除。没有压缩/降采样/自动清理/迁移。

只读盘点：2026-09-16 当前开发资料库约 9.21668 GiB，WAV 9.21567 GiB，23 组音频；已有保留 1 组。Flowers of Romance 六轨和整曲弦乐各约1.62434 GiB。数字为扫描时文件逻辑体积，不是已释放的磁盘空间。未删除用户现有结果。

清理单位：整个已识别运行目录，包含 WAV 与 README。保留很小的机器索引，缺少文件自然判定为未生成；回收站恢复原目录可恢复旧索引可用性，但重算后索引被更新时不承诺自动重新选择旧结果。MIDI、原曲、模型、段落结果和人工标注不在清理对象中。存在仍在磁盘上的 refinement 或 MIDI 依赖时，基础分轨禁止清理；批量选择额外跳过当前基础分轨，手动可选择无依赖的当前分轨。

保留：复用 refinement/kept 中历史标记，新标记存在运行目录 .xld-keep.json；refinement.read 同时读取两者。取消保留同时移除本运行标记和匹配的旧 kept 指针。没有覆盖原机器结果。目录内有未知文件/链接则不能清理或修改标记，可打开目录自行检查。

删除：只接收 id/revision；服务重新扫描定位，不信任前端路径。root/目录每层 lstat+realpath 拒绝链接与越界，目录只能来自扫描器固定结构和 UUID，目录内容以大小/mtime 指纹比较。确认前后与逐目录操作前再次检查，未知/变更中止。默认回收站，失败不会降级为永久删除。永久删除明确选项 + 原生弹窗，默认按钮和取消按钮均为取消。多项中个别失败会返回部分成功数量和错误。

并发：服务和 UI 禁止分析/批任务期间清理，清理/标记锁阻止本窗口启动分析和更改资料库。原生确认框期间持锁，确认后重检资料库和文件。其他旧版应用实例不共享全局锁，请避免同时用旧实例改同一批文件；本版按变化重检降低冲突，不声称跨进程事务。

验证：XLD npm test 全套通过；临时夹具覆盖体积、旧/新保留、refinement/MIDI依赖、忙锁、变化拒绝、取消确认、永久删除、模拟回收/恢复、路径攻击与 junction 保护。真实 Electron shell.trashItem 在仅64字节临时 WAV 的独立目录上成功；受限环境先拒绝 OS 删除，正常权限重测通过，未回退删除方式。控制器测试覆盖筛选、批选排除、默认回收、刷新及忙状态。候选包9组运行环境检查和发布 shell 测试通过。UI 为 DOM 控制器测试，未执行真实窗口视觉验收；没有绕过浏览器限制。用户本机开发版，未声称干净 VM 测试。

文件地图：core/storage.cjs（扫描/保护/删除）、storage-controls.js（弹窗列表）、desktop/main.cjs/preload.cjs（IPC与原生确认）、core/refinement.cjs（保留兼容）、app.js/index.html/style.css、tests/storage*.cjs、发布说明。

限制：仅管理当前根目录内当前 album/track 输出结构的 stems/refinement 运行目录；所有其他文件计入体积，但不能批删。扫描需等待，不做后台自动定时扫描；数据量远大于当前目录时可能要做增量/分页。无强制删除带MIDI依赖的基础分轨，防止工作台关联失效。下一版按用户需求考虑跨盘归档或只保留目标；FLOAT→FLAC不作为无损浮点归档方案。

复现：npm test（source/xld-runtime-baseline）；node audit.cjs 只读扫描真实资料库；Electron test-trash.cjs 只对新建临时文件夹测试 OS 回收站；发布 verify.cjs/check-runtime.cjs。publish-plan.json 记录源文件前后哈希，发布前备份保存在原缓存工作区 before/。
