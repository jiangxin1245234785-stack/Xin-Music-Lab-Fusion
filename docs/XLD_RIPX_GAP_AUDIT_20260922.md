# XLD 对标 RipX：功能差距与当前实现审查
日期：2026-09-22
基线：XLD core.59 / XML stems.13；开发包 releases/0.5.0-dev.export.1。

本轮是分析审查，不是新版交付。未修改产品源码、发布包、模型或用户音乐结果；未运行 GPU 推理。核对官方资料、当前源码、既有 R11 验收记录，并在内存中运行针对性探针。播放探针使用 AudioContext 替身验证控制与路由，不能替代真实设备听评。

## 判断

下一阶段最值得投入的是“统一试听与人工校对”，而非继续堆模型。XLD 已具备自动生成初稿、基础音符修改、独立人工版本和导出，但这些功能还没有组成一致的多轨工作环境。

RipX 的分轨→定位声部→试听→纠正→导出流程值得对标。它的原音频逐音符编辑则是独立的大工程：Rip Audio 保存音符及谐波等声音信息，编辑后重建声音。XLD 修改 MIDI 不会修改对应 WAV；加 M/S 和 MIDI/WAV 选择也不会自动获得这项能力。[官方 Rip Audio 说明](https://hitnmix.com/rip-audio/)

官方功能介绍不能证明 RipX 对 MEGURI 或 WEG 的识别质量比现有模型好。我们没有做同一输入、同一区间、同一种试听音源的对照测试，不给转谱质量排名或“完成百分比”。

## 现有能力与差距

| 环节 | XLD 当前实际能力 | 还缺什么 |
|---|---|---|
| 分轨 | 基础分轨、Mega53 细分、结果缓存、音源身份与保存管理 | 把来源有重叠的结果组织成可正确试听的轨道关系 |
| 转谱 | 多声部模型、默认与备选、一键 MIDI | 新模型结果的低成本片段对照；不靠模型名字让用户猜用途 |
| 结构观察 | 段落、和弦、音符在统一时间轴，人工标注、演奏方式/和声条带 | 解释层错误修正；人工标注如何成为分析依据需要明确 |
| 钢琴卷帘 | 多乐器显示、全曲与聚焦、缩放平移、单选/多选/框选 | 概览即可混合试听；选区波形/频谱辅助核对 |
| 基础编辑 | 补删音、移调/移动、改起止/力度、撤销重做 | 同音高合并、拆分、复制粘贴、空轨/清空操作、鼓类别操作 |
| 试听 | 聚焦单 MIDI 乐器的合成试听；同位置 WAV/MIDI 切换；循环 | 多轨同步 M/S、统一音量和播放控制、混合来源试听 |
| 演奏表达 | 保存会保留并校验原有弯音和控制事件 | 这些事件的显示、播放解释、编辑及移动时的关联规则 |
| 版本 | 原稿/人工版分开、草稿恢复、切版、保留与删除 | 临时 A/B 不改变正式使用版本；融合对草稿的一致处理 |
| 输出 | 已存完整声部 MIDI 原字节导出；保存版多声部融合 | 当前内部乐器/选区/选定轨导出、外部修改后导回 |
| 节奏 | 按真实秒数保留时间，不强制量化 | 可修正的拍点、小节、拍号与速度图；可选节拍参照 |
| 原音频编辑 | WAV 是只读参考音源 | 原音频逐音符变调、音色/谐波编辑、原音色重合成未实现 |

RipX 基础版的 M/S、速度调整和音符操作可查[官方 DAW 页面](https://hitnmix.com/ripx-daw/)；声部重分配和导出流程见[用户提供的官方教程](https://hitnmix.com/2024/02/14/ripx-deepremix-for-midi-file-extraction/)。PRO 的音符合并/拆分、音高曲线与谐波工具见[官方 PRO 页面](https://hitnmix.com/ripx-daw-pro/)。表中 XLD 内容来自本地实现，非根据历史截图推断。

## 应先修的实际问题

### 1. 底部播放器与 MIDI 试听不受同一套控制

内存探针已复现：
- MIDI 正在播放时，底部音量设为 0，只改变 HTML audio 的音量；MIDI 合成总线仍为 0.7。
- 底部进度条跳到 30 秒，仅移动 HTML audio，MIDI 试听仍沿原时钟运行。
- 点底部播放键会启动 HTML audio 并停止 MIDI，而不是暂停正在听的 MIDI。
- Mega53 细分试听启动后，MIDI 仍可保持播放，存在叠播路径。

证据：
- [app.js](../source/xld-runtime-baseline/app.js)：1415–1418、1431–1443、1722。
- [audition-controls.js](../source/xld-runtime-baseline/audition-controls.js)：独立 AudioContext 与 bus。
- [refinement-controls.js](../source/xld-runtime-baseline/refinement-controls.js)：106。
- 探针与结果：D:/Caches/codex/ripx-audit-20260922/playback-probe.cjs、playback-probe-results.json。

性质：已确认控制逻辑问题；并非声卡、驱动或实际听感测试。相关源文件与 export.1 中对应文件一致。

修复目标：当前正在听的来源，无论原曲、WAV 还是 MIDI，都接受同一个播放/暂停、跳转、主音量与循环控制。切换页面不能留下隐形播放器继续发声。

### 2. 转谱页的“试听”并不是生成的 MIDI

derived-controls.js:414 的 derivedMidiAudition 调用 switchAudio，输入来自声部 audioUrl，播放的是转谱输入 WAV。真正 MIDI 合成试听在时间轴，需要聚焦音符轨。

用户可能把“输入 WAV 好听”误当成“这份 MIDI 好听”。这是入口与命名问题，不是新增一个合成器就能解决。

应让转谱页和时间轴总览都明确显示来源：WAV / MIDI、声部、使用版本、是否草稿。用同一个播放入口；没有 MIDI 时只禁用 MIDI 选项，仍允许听 WAV。

### 3. 融合会静默忽略未保存草稿

导出 MIDI 已有草稿检查；融合按钮、IPC 和融合服务没有同等检查。它们只读取当前已保存的 active MIDI。

因此可以出现：时间轴显示并试听修正版草稿→点融合→成功输出旧保存版。当前代码链路可以确认；本轮未在真实用户文件上执行融合。

证据：
- derived-controls.js:55、524；
- desktop/main.cjs:913；
- core/analysis-service.cjs:260；
- core/midi-merge.cjs:23；
- 对照导出保护 desktop/main.cjs:992、1001。

建议默认先保存相关草稿再融合，或者明确选择“仅使用已保存版本”。不能自动把草稿当成已保存，也不能不提示就忽略。直接融合和一键 MIDI 的最终融合必须一致。

### 4. 延音跨和弦边界时，和声统计会漏音

timeline-controls.js:199–210 按音符起点取当前和弦里的音符，之前开始但仍在持续的音被排除；classifyHarmony 又用未裁剪的完整音长加权。

内存复现：C4 从 0 秒响到 4 秒，和弦 C 在 0–2 秒、Db 在 2–4 秒。后一段被判为 rest，虽然 C4 仍在响。

这直接影响弦乐、钢琴踏板延续以及吉他长音分析。和声统计应使用“与区间重叠的发声音符”，持续时间裁剪到区间；起音型节奏/演奏方式统计应保留独立规则，不能一起粗暴替换。

### 5. 人工和弦标注没有进入和声条带的依据选择

timeline-controls.js:183 的 referenceChords 优先选 chord-chordmini、chord-btc 等模型结果，不读取人工和弦标注。人工标注目前是独立观察层。

不能简单认定“所有人工标签都自动覆盖”，因为它们也可能是备注。应区分“备注”与“已确认修正”，并让用户选择有效参考：
- 已确认人工区间覆盖对应模型区间；
- 未修正区间继续采用所选模型；
- 明示当前参考，多个重叠人工修正需确定优先规则。

否则“我已改正确”的和弦，与下方的关系提示仍会矛盾。

### 6. 部分和弦标签解析有确定错误

timeline-controls.js:34–53 中扩展音统一加入 9/11/13，且不完整处理和弦性质及变音。

原函数内存执行（以 C 为 0 的音级）：
| 标签 | 通常含义的音级 | 当前计算 |
|---|---|---|
| C9 | 0,2,4,7,10 | 0,2,4,5,7,9 |
| Cmaj9 | 0,2,4,7,11 | 0,2,3,5,7,9 |
| Cm7b5 | 0,3,6,10 | 0,3,7,10 |
| C7b9 | 0,1,4,7,10 | 0,2,4,5,7,9,10 |

例如持续 F 在 C9 上被标成“完全一致”。探针见 D:/Caches/codex/ripx-audit-20260922/harmony-parse-probe.cjs 与 harmony-parse-results.json。

修复应从当前模型实际标签集合出发，解析不了就显示“未知”，不能默认凑成某个和弦。即便解析正确，“和弦外音”也不等于演奏错误；WEG 的紧张音、经过音和音色噪声都不能凭颜色自动删掉。

### 7. 没有 MIDI 的声音尚未进入统一轨道总览

当前时间轴由 MIDI 成果构建；只有 WAV、尚未转谱或不可转谱的声部没有完整轨道入口。已有 WAV 而 MIDI 音符数为零时，时间轴 WAV 试听也被禁用（探针已复现）。对 WEG 的电子环境声与 glitch，这会让“无法转成音符”误变成“没有声音可分析”。

应从可用音源建立轨道，MIDI 作为可选层叠加；纯 WAV 轨也可以 M/S、循环、显示波形和人工标注。证据：desktop/main.cjs:582、audition-controls.js:283、403–404。

## 已知限制，不能混称为程序故障

- 空结果不能补第一个音；一条乐器的最后一个音不能删除。midi-edit.js:6 与编辑入口明确限制。底层读取空乐器会改变后续乐器索引，需要先定义稳定身份/清空语义，不能只去掉按钮禁用。
- 同一声部同一版本可以逐个修改多个乐器，但不能同时留下多条乐器的未保存草稿；需要先保存或撤回当前乐器。midi-editor-controls.js:76。
- 当前导出包含整个声部文件。聚焦 strings 内的小提琴，并不意味着只导出小提琴；现有提示已说明这一点。
- 弯音、踏板和其他控制事件保存时会保留；当前编辑界面主要操作音高、起止、力度。移动音符不等于同时移动同通道表达曲线。表达常作用于通道，不能无条件跟随一颗音符挪动。
- 合成试听适合校对音高、起音和大致长度，不足以重现原吉他/弦乐音色；也没有完整 MIDI 表达渲染。鼓的尾音不能只靠拉长 note 修正。
- 导出的固定 120 BPM 是秒数到 MIDI tick 的编码时间基准，不是测出的歌曲速度。runner.py 标明 fixed-timebase / quantized:false，merge.py:43 使用固定时间基准。
- 当前没有应用内外部 MIDI 编辑往返；导出到 FL Studio 后，仍欠缺带起点/速度核对的导回流程。

这些限制需要显式展示，避免把“导出无损保留字节”与“能在应用内完整听出所有 MIDI 信息”混为一谈。

## M / S 与 WAV / MIDI 应怎样设计

沿用时间轴，不再增加一张大型工作台。转谱页负责生成和版本选择，时间轴负责总览试听与修正。

每个声部轨头使用一条紧凑控制：
**声部名 · M · S · WAV / MIDI · 音量**
轨头详情才展示模型、源文件和版本。选中轨头进入编辑，不自动独奏。隐藏轨道也不自动静音。

全局播放器：
- “原曲 / 工作混音”切换，在同一时间位置 A/B。
- 播放、暂停、定位、循环、主音量只保留一套。
- 提供“全部用 WAV”“有结果的轨用 MIDI”快捷预设；用户随后可逐轨修改。
- 没有 MIDI 的轨道保持 WAV 并明示，而非静默消失；另提供显式的“仅 MIDI”比较。
- 显示当前声音组成，例如“吉他 MIDI · 其余 WAV”，以及未保存草稿标记。

M/S 规则：
- M 只改变监听，不删除文件、不改模型结果，默认不影响 MIDI 导出。
- S 可多选，用于单听弦乐，或弦乐+吉他共同听。
- 静音优先于同一轨独奏；明确显示“因其他轨独奏而暂时不发声”，提供清除全部 M/S。
- 原曲模式播放的是整首混音，逐轨 M/S 不能直接把原曲中的某乐器移除。想听“去掉吉他”的版本，应进入工作混音。
- 导出范围独立选择，不暗中根据 M/S 排除用户的数据。

### 必须先解决声部与子乐器的层级

一个 strings WAV 可以产生 violin、cello 等多条 MIDI 乐器。这些子乐器不是自动得到的独立 WAV：
- 父声部 WAV 模式只播放该 WAV 一次。
- 切到 MIDI 模式后，子乐器可分别 M/S。
- 没有单独小提琴 WAV 时，不能让用户误以为在 WAV 模式静音 cello 就能把录音里的大提琴删掉。
- 可用折叠父轨“弦乐”，展开显示 MIDI 子轨；WAV 对照显示为组级声音。

### Mega53 结果不能无脑加入全套基础分轨

core/refinement.cjs 支持从原曲、other、guitar 等不同父音源提取，记录 parentRunId/sourceStem/timeOrigin，并验证 target + residual 的重建关系。

若弦乐来自 other，应该用“弦乐 target + 对应 residual”替代 other；不能同时播放 other、target 和 residual。若弦乐从整曲提取，target+residual 属于原曲的另一种分解，不保证和既有 bass/guitar 等轨不重叠。多个独立提取的 target 也不天然互斥。

最小实现：默认混音只使用一组共同来源且可互补的分轨；细分结果通过替换其父源进入。无法确认互补关系的组合只作清楚标注的对照试听，不称为原曲还原。

## 补齐功能的实际顺序

| 轮次 | 范围 | 交付判断 |
|---|---|---|
| A：一致性修复 | 播放/主音量控制冲突；试听来源标签；融合草稿检查；延音与和弦解释错误 | 同一位置看到、听到、保存和输出的版本一致；主音量归零确实静音 |
| B：多轨试听 | 先多 MIDI 轨 M/S，再接共同来源 WAV 混播和逐声部 WAV/MIDI 切换 | 在总览听“弦乐 MIDI + 其余 WAV”，切换不跳时、不双响 |
| C：高频修正 | 同音高合并/拆分、复制粘贴、空轨补音/清空、鼓类别、单乐器与选区导出 | 能修好一段揉弦碎音，不必逐颗拉尾巴；可撤销且原稿保留 |
| D：听辨与外部往返 | 改善试听音源；显示踏板/弯音；FL Studio 导回、版本 A/B、局部波形辅助 | 应用里与外部听到的差异可解释，修改可以带回分析 |
| E：节奏与分析 | 可校正拍点/速度图、选区统计、人工动机标注 | 秒数与小节可换算，变速歌曲不被强制量化 |

B 不应一口气变成 DAW 混音器：先 M/S、来源和音量，声像可后补，暂不做发送、效果链或录音。C 的合并默认仅处理同一乐器、同音高、明确选中的音符，并预览前后；揉弦、真实重复拨弦、滑音、失真残留不能一律合并。

改良试听音源可保留现有轻量参考音色，并允许用户自配乐器音源。先解释已有踏板/弯音，再谈手绘曲线；普通 MIDI 通道弯音会同时影响同通道多音，需要明确通道约束。

## 实现上保持简单，但不能省的边界

1. XLD 继续拥有分析、人工修订、监听状态；XML 消费结果，不迁回模型计算职责。
2. 时间轴视图不是播放器本身。为原曲/WAV/MIDI 共用一个播放会话，分别提供音源。
3. 分开保存：音源身份、使用版本、未保存草稿、监听开关。Mute 不写入音符数据，切换试听版本不自动激活正式版本。
4. 多轨共用时间基准；跳转、循环边界、暂停/续播需处理正在延续的音。切换来源用短淡入淡出，避免爆音。
5. 单轨试听当前有 64 复音上限，多轨不能直接沿用而不评估；否则长弦乐可能在播放器中被抢断，再次误判为转谱问题。
6. 不把几十条整曲 WAV 一次性解码进内存。10 分钟、48 kHz、双声道 float32 约 220 MiB/轨，六轨仅解码数据约 1.29 GiB，尚未算复制和界面。按需载入、区间缓存或流式播放需要实测后选定。
7. 对照听感需可控音量，并给总线留余量、显示过载；不能把更响误当成识别更准，也不能无提示给每轨独立归一化破坏平衡。
8. 改善公开版安装和模型环境指引另排，不把本次开发机通过视为正式跨机器验收。

## 最小验收集

不另建大型评测平台，先用一段 MEGURI 弦乐/吉他和一段 toe 鼓节奏：
- 全 WAV、全可用 MIDI、单轨替换三种试听，同位置切换。
- M/S、主音量为零、暂停/继续、进度跳转、循环边界，都控制当前声音。
- 切到分轨细分页面后，不残留另一播放器发声。
- strings 父 WAV 不因多个子乐器重复响；细分替换父源没有双计。
- 长音跨和弦边界仍被统计；人工修正被选为参考后条带随之变化。
- 草稿在试听、融合、导出中的处理有一致提示。
- 修复一组确认的碎音、撤销、保存、重开、导出到 FL Studio 对照。
- 较长曲目下观察内存、播放漂移、过载与掉音；记录错误，不跑昂贵模型来替代交互验证。

既有 R11 报告已证明保存后的修订、融合与整声部导出可以一致，原始 MIDI 哈希不变。这是值得保留的基础。本轮发现的是未保存草稿和多入口播放等尚未统一的边界，不需要推倒现有版本系统。

## 定位取舍

优先做到：**可换模型的本地音乐分析与人工校对工作台**。
现有价值是可替换模型、保留来源与版本、段落/和弦/音符共同观察，以及面向复杂曲目不断试验的工作流；这些是项目侧重点，不能据此断言其他软件完全没有。

暂缓：原音频谐波编辑、原音色逐音符重合成、VST 宿主、录音、复杂自动化、自动整曲“修正”。WEG 的 glitch/环境声也不必全部压成 MIDI，保留可试听、可标注的 WAV 轨本身就有分析价值。

建议下一轮先交付 A，然后 B。完成后，用户在总览就能做“保留原伴奏、只替换一个 MIDI 声部”的判断，后续音符修正才有可靠的听辨依据。
