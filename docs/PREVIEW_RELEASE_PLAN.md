# 第三方试用版准备

状态：**准备中，尚无独立电脑验证通过的通用安装包。** 这是下一轮工作的具体范围，不是已发布功能清单。

## 先交付什么

先做 Windows 小范围试用，保留 XLD 与 XML 两个入口、现有模型默认和工作流程。不需要等待完整模型更新页、MIDI 编辑器或歌曲比较系统。

首批试用可以由开发者协助安装模型；未安装模型应显示“未安装”，已安装模型必须可用。不要求第一轮就实现全自动下载管理或所有硬件支持。

## 已发现的实际问题

| 位置 | 当前问题 | 第三者遇到的影响 |
|---|---|---|
| history.1/runtime.json | 21 个 paths 条目均为原开发机绝对路径 | 换电脑后无法定位环境与权重 |
| history.1/development-settings.json | 写入开发者曲库和实验分析目录 | 首次启动找不到曲库，或输出目录不符合用户选择 |
| build-local.cjs | 保留输入配置中的绝对路径，仅换算相对输入 | 现有构建可能继续把个人目录带进下载包 |
| configure-bundle.cjs | 基础环境 / refinement 参数已有，YourMT3 和 MuScriptor 的配置生成尚未覆盖 | 不能靠旧脚本自动生成最新模型的完整配置 |
| runtime-config.cjs | 多项基础环境仍为必填 | “小主程序 + 可选模型”尚未完全独立，需要最小改造 |
| MuScriptor Python | 当前实际指向 yourmt3-v1/python.exe | 不能按界面模型名独立删除或漏发共享环境 |
| 运行环境 | 基础环境虽已有隔离工具，附加环境仍需搬迁与路径核对 | 复制目录不等于独立可用 |
| 随包离线帮助 | 多轮追加，仍混有四声部 / 历史配置说明 | 与当前五声部可选流程不完全一致，需要统一 |
| ADTOF vendor/PROVENANCE.md | 原记录标明此 pinned 源码未含 LICENSE，公开再分发状态未核实 | 对外包不能仅凭“仓库可下载”就直接捆绑 |
| 发布验证 | 主要是开发机和隔离数据目录验证 | 无法宣称其他电脑无需 Python 即可完整运行 |

上述来自当前本地代码和配置核对；不是第三方许可的最终法律结论。许可与授权未核实的组件应先排除出对外包，或完成确认后再纳入。

## 下载包的目标结构

用户拿到的目录建议只暴露必要入口：

```text
Xin-Music-Lab/
  XLD.exe                  分析工作台
  XML.exe                  音乐可视化
  README.md                从哪里开始
  使用说明.html             离线帮助
  检查环境.cmd              诊断入口
  runtime.json             由安装 / 配置工具生成
  resources/               应用资源及第三方声明
  runtime/                 已安装的共享分析环境
```

这是下一轮目标布局，不是当前 ZIP 已具备的结构。用户的模型和分析资料库通过配置选择独立位置；生成音频不应放进程序安装目录。

主程序、运行环境、模型需要可分别更新，但先复用已有 runtime 和 release-tools；不另建复杂插件平台。不把每个声部都打包一份 MuScriptor Large，也不按模型名称误删共享 Python。

## 工作拆分与验收

### A. 用户文档与入口（本轮）

- [x] README 改为功能、获取状态、上手入口、硬件边界与反馈。
- [x] 原开发首页归档，单设开发入口。
- [x] 编写快速上手与常见问题。
- [x] 重写两份随包 README 模板，移除开发者曲目与实验路径。
- [x] 列明下载包目前不能独立运行的原因。
- [ ] 下一轮将相同内容同步到随包离线 HTML 帮助并验证实际显示。

### B. 可搬迁的试用包（下一轮第一项）

1. 新建独立预览包目录，不修改已在用的 history.1。
2. 构建时排除 development-settings.json、用户设置、测试音乐、token 和历史输出。
3. 统一生成相对或用户选择的 runtime 路径；补齐 MuScriptor / YourMT3 配置与共享依赖关系。
4. 启动时让用户选择曲库与分析资料库；无效路径可重新选择，不借用开发者目录。
5. 检查哪些环境可以复用、哪些必须重建；依赖、源码和权重各自记录来源、版本、哈希与条款。

验收：移到一个包含中文与空格的全新目录，隐藏原开发目录后仍能启动与运行目标功能；配置中没有原个人目录。仅在原目录能跑不算通过。

### C. 模型就绪与故障反馈

1. 显示“已安装 / 未安装 / 缺环境 / 需上游授权”，不要统称不可用。
2. 缺一个可选模型不阻止其他模型使用；模型切换不隐式降档或下载大权重。
3. 选择模型前能看到预估下载大小与已经验证的设备条件；初期手动安装也可，但步骤必须准确。
4. 保留已有进度、取消、结果缓存；失败后提示缺哪一步，并能生成诊断摘要。

验收：只安装一组支持的模型也能完成对应工作流；缺失或无权限目录给出可理解提示；诊断分享可去掉个人路径与凭据。

### D. 发布素材与首次独立验收

1. 用自制或有分享授权的短音频制作演示，不把商业歌曲分轨作为下载样例。
2. 核实可随包分发的第三方源码、依赖与权重；保留署名，不擅自给第三方文件换许可证。
3. 在无开发环境的 Windows 上测试启动、目录选择、播放、分轨、所承诺的 MIDI 路径、取消重试、重启恢复、清理、XLD/XML 往返。
4. GPU 推理在声明支持的真实 GPU 机器上验证；没有 GPU 的 VM 只能覆盖其实际能力范围。
5. 提供版本说明、支持矩阵、已知问题、下载文件哈希和反馈入口。先以 Preview 发布，不标稳定版。

验收记录必须区分：代码测试、搬迁测试、干净系统测试、真实模型运行、人工试听。首次发布可以只承诺已验证的 Windows / GPU 组合，不需要同时解决所有平台。

## 发布方式

首轮优先通过当前私有仓库向少量获授权试用者发包。仓库公开、源码许可确定、可再分发安装包发布是三个不同决定；本轮不改变仓库可见性，也不创建下载 Release。

准备好后，在 GitHub Releases 提供主程序及必要环境的清晰下载项，模型按已核实上游规则获取。首页只指向当时真实可用的版本，不放失效开发路径或“即将上线”的假下载按钮。

## 完成标准

第三者不需要知道开发者姓名、个人磁盘路径、实验目录或安装过哪些研究项目，就能按说明完成至少一条承诺的工作流。遇到失败时，能知道问题出在哪一步并反馈。
