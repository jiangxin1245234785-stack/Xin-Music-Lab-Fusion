# XLD 存储空间优化项目企划书

- 日期：2026-10-03；版本：v1.0。
- 状态：规划完成，尚未实装；本次没有转换或删除分析音频。
- 开发基线：本地 `0.5.0-dev.workbench.9`，XLD `core.70`，XML `stems.13`。
- 执行原则：个人项目，小步交付。先减少重复文件，再接入压缩；已有试听、转谱、编辑和导出功能不能丢。

本轮目标是降低长期保存分轨和细分结果的空间成本。首先让一份弦乐细分只保存必要的新音频，再验证能完整保留模型输出的压缩格式。优化存储不重新运行分轨模型，也不改变已有 MIDI 或人工修订。

## 1 现状与可获得的收益

2026-10-03 只读扫描当前分析目录：约 **26.83 GiB**，其中 WAV 约 **26.80 GiB**，共 29 组音频，包括 16 组基础分轨和 13 组细分。这里统计的是文件逻辑大小，不等于最终可释放的磁盘空间。

当前基础分轨和 Mega 细分均保存 32 位浮点 WAV。以《100 years of choke - 百年の窒息》为例：时长 824 秒、44.1 kHz、双声道，每个 WAV 约 277.24 MiB。

| 结果 | 当前保存内容 | 当前大小 | 去重后的目标 |
|---|---|---:|---:|
| 基础六轨 | bass、drums、guitar、other、piano、vocals | 1.624 GiB | 本阶段仍保留六轨 |
| 弦乐细分 | original、target、residual，以及三份 listen 试听副本 | 1.624 GiB | 只保存 target、residual，约 0.541 GiB |

这首歌的 `original.wav` 与对应父轨 `other.wav` **PCM 采样哈希一致**，可以用引用替代；两者 WAV 文件整体哈希不同，原因在容器而非采样内容。因此，去重必须比较采样和音频规格，不能只比较文件名或整文件哈希。

三份试听文件用于统一降低音量：该组记录的增益约为 0.919，输入峰值约为 1.033。改成播放时应用增益，即可不再保存试听副本。目标与剩余声部仍需保留，不能把剩余声部当成垃圾文件。

该样本的细分目录预计可减少约 **1.083 GiB，即 66.7%**；基础六轨与这份细分合计从约 3.249 GiB 降至 2.166 GiB，减少约 33.3%。这不是整个资料库的节省比例。全库须逐组检查，压缩收益另行实测。

## 2 本轮范围与默认决策

| 项目 | 本轮决定 |
|---|---|
| 输入副本 | 经校验与父音源相同后，改为引用指定父结果与采样区间 |
| 试听副本 | 用播放增益替代，保持当前试听音量行为 |
| 新建结果 | 第一轮仍用浮点 WAV，只减少副本 |
| 压缩格式 | 优先验证 WavPack 无损模式；通过验收后作为新结果的默认存储，WAV 保留为兼容选项 |
| FLAC | 24-bit FLAC 只做对照实验，本轮不自动替换浮点母版 |
| 旧结果 | 用户在存储管理中主动选择优化，支持逐组处理和批量队列 |
| 模型 | 默认模型、参数、权重和声部分离逻辑不变 |
| 产品分工 | XLD 管理音频存储、读取和迁移；XML 继续消费结果与可播放音源 |

WavPack 可以无损保存 32 位浮点音频，但需要验证项目所用解码路径确实保留浮点数据；只允许无损编码模式，不启用有损混合模式或降低浮点精度的选项。[WavPack 官方文档](https://www.wavpack.com/wavpack_doc.html)

FLAC 不支持浮点采样。32 位浮点 WAV 转为 24 位整数 FLAC 涉及精度变化；峰值超过 1 的数据还需要明确的幅度处理，不能直接裁剪。即使试听差异很小，也不能称为原始模型输出完全无损。[FLAC 官方说明](https://www.xiph.org/flac/faq.html)

本轮不做 MP3 等有损母版、不降采样、不重训模型、不接云存储、不搭建通用插件系统，也不按期限自动删除用户分析结果。如果压缩格式的播放或打包验证不通过，先交付去重版本，继续保留 WAV。

## 3 保存与读取规则

### 3.1 只保存新的音频内容

新的细分结果保存 `target` 和 `residual`，原输入记录为来源引用。引用指向具体父结果，不能指向“当前选中的 other”，避免切换分轨版本后悄悄换源。

整曲引用包括父结果标识、声部、采样率、声道和采样数。片段细分另外记录起始采样和长度。只有确认没有额外重采样、混音或其他预处理，且对应采样相同，才替换输入副本；否则保留 original 并说明原因。以原曲为输入时，继续检查原曲是否存在或被修改。

引用仍被使用时，父音频不能被清理。沿用现有依赖保护；“只保留细分、同时删除它唯一依赖的父音源”不属于可清理组合。本轮不做跨歌曲、跨资料库去重，也不用硬链接代替明确的来源关系。

### 3.2 将试听增益与母版分开

单独比较 original、target、residual 时，按记录的共同增益试听；MIDI 转谱和后续分析读取原始幅度。轨道混播继续使用原始互补音频和现有总输出限幅，不把细分试听增益重复乘入混音。

这项改动要覆盖细分播放器、单轨 WAV 试听、时间轴混播和导出。不得只改一个按钮，再留下其他入口对 `listen-*.wav` 的依赖。标准 WAV 导出保留浮点母版；需要与旧 listen 文件等效的输出时，提供“试听音量”选项，并在导出时生成。

### 3.3 音频身份不跟着文件扩展名改变

现有结果校验多处依赖路径、大小、修改时间和 `.wav` 扩展名，直接改名会导致 MIDI 或细分被标记为失效。改动应集中在一个小型音频读写模块，提供：解析来源、读取规格、按采样范围读取、提供临时 WAV。

模型结果的身份继续由曲目、runId、声部和内容决定；编码方式、物理路径、解码缓存是存储信息。无损换格式后，runId、活动版本、MIDI 来源、人工修订和草稿关联保持不变。

旧记录通过明确的迁移映射解析到新文件：映射同时保留旧身份与已验证的采样摘要。不能跳过来源校验、伪造大小或修改时间，让“失效”提示消失。音频内容被外部修改时，仍应正常报失效。

### 3.4 有界解码缓存

试听优先按需读取，不能每次拖动时间轴都完整解压所有音轨。确实只接受 WAV 的转谱后端，通过临时解码入口获得浮点 WAV，结束后释放。

首版拟将可回收解码缓存上限设为 2 GiB，并提供清空入口。正在播放或转谱使用的文件不被驱逐；单个任务需要更多临时空间时，在开始前显示所需空间，用完回收，不静默突破缓存限制。取消和失败也要回收临时文件。缓存大小与正式音频分别统计。

## 4 压缩验证与采用条件

使用真实曲目的副本测试，不批量转换正式资料库：

- 《100 years of choke》：验证六文件变两文件、超范围峰值和父轨引用。
- 《MEGURI》：覆盖失真吉他、持续弦乐、鼓和稀疏钢琴，评估压缩与多轨跳转。
- toe《goodbye》：如本机结果可用，检查鼓点和镲片尾音。
- 补充一个细分片段、一个没有生成 listen 副本的结果，以及两份来源版本不同的 MIDI。

记录 WAV、WavPack、实验用 24-bit FLAC 的文件大小、编码耗时、首次播放准备时间、随机定位延迟、CPU/内存和临时磁盘峰值。稀疏声部和噪声较多的声部分开列，不预设“必定省一半”。

WavPack 进入正式存储的条件：

1. 全部验证样本解码后的 float32 采样逐位一致，采样数、声道、顺序和时间起点不变。
2. 不裁剪超过 1 的峰值；目标与剩余相加的重建误差不因存储增加。
3. 同一首歌多轨播放、循环、定位和音源切换无新增掉音；性能与当前 WAV 基线对照记录。
4. 转谱后端实际读到相同输入；旧 MIDI、人工修订和融合结果可继续使用，无需整库重新转谱。
5. 在本地打包版中验证依赖和相对路径；第三方发布另做无开发环境验证，不能以本机通过替代。

格式采用同时看压缩收益和访问速度。某个文件压缩后不更小，保留 WAV；不为了统一扩展名而浪费空间。

## 5 旧结果迁移

以一组结果为提交单位，队列串行执行，避免同时复制整库占满磁盘。迁移顺序为：

**扫描与预估 → 检查引用和剩余空间 → 写入临时结果 → 解码校验 → 切换存储记录 → 从界面重新读取 → 清理旧副本。**

第一轮先在隔离副本验证，再开放单组操作，最后开放批量。正在生成、播放、转谱或导出的结果暂不迁移，同一结果不能同时修改。复用现有任务状态并增加轻量占用检查，不建设跨机器任务系统。

必须保留的小型保护措施：

- 提交前保留原文件和旧记录；验证失败或取消时，旧结果仍可用。
- 每组有少量阶段记录；中断后能判断继续清理还是回到旧记录，不依赖猜测。
- 切换后核对活动来源、保留标记、依赖关系、MIDI 版本与草稿，再处理原文件。
- 默认旧副本移入回收站；界面明确“整理完成”和“磁盘空间已释放”的区别。永久删除沿用现有明确确认机制。
- 压缩后的音频可重新导出或恢复为浮点 WAV。删除旧副本后，恢复依赖解码和额外空间，不承诺零成本回退。
- 老版本程序不保证能读取迁移后的新记录。不要让新旧版本同时写同一组数据；继续使用老程序前，应先恢复兼容 WAV 与记录。

迁移不改原曲、不删除 MIDI，不用重新推理替代格式转换，也不因无法识别一个历史结果就连带中断整个队列。无法验证的组保留原样并列出原因。

## 6 存储管理界面

复用“资料库 → 存储管理”，不新增一个独立产品页面。

| 位置 | 新增或调整内容 |
|---|---|
| 顶部摘要 | 正式音频、重复副本、临时缓存；逻辑大小与实际释放空间分开表述 |
| 单组结果 | 存储格式、物理文件数、引用来源；展开可看母版、输入副本、试听副本和缓存 |
| 操作栏 | “优化冗余副本”“无损压缩”“清理缓存”；压缩后提供“导出 WAV” |
| 执行前 | 范围、可确定的去重收益、临时空间需求；压缩收益标为估算或待测试 |
| 任务进度 | 当前歌曲、准备/校验/切换/清理阶段、取消；完成后显示成功、跳过、失败 |
| 完成摘要 | 优化前后大小、旧副本去向、估算释放量或实测磁盘变化 |

被引用的父音频不重复累计到细分组的文件体积。有关联结果的“不可整组删除”状态，不应一并禁用安全的存储优化；两种操作分别检查条件。保留标记随迁移保留，不能被解释为允许删除音频内容。

## 7 分轮任务和周期

以下是单人有效开发时间估算，不是固定交付日期。每轮保留可运行版本；第一轮通过后即可先使用，不必等压缩功能完成。

| 轮次 | 任务与交付 | 预计时间 | 通过条件 |
|---|---|---:|---|
| S0 | 只读盘点、格式试验、确定编码解码工具及分发方式；保存小型基线报告 | 0.5–1 天 | 采样校验方法和浮点支持明确，不下载模型或重跑分轨 |
| S1 | 来源引用、动态试听增益、旧格式兼容；新结果不再生成冗余副本，单组去重可验收 | 1.5–2.5 天 | 示例细分只保留两份必要音频，试听和 MIDI 关联不变 |
| S2 | WavPack 存储、统一读取、解码缓存和 WAV 导出 | 1.5–3 天 | 通过第 4 节条件；不通过则保留 S1 的 WAV 方案 |
| S3 | 存储管理批量优化、取消与恢复、完整回归、独立开发包和交接 | 1–2 天 | 在真实样本副本上验证迁移前后全部主要操作 |

完整范围预计 **4.5–8.5 个有效开发日**。最先可交付的去重版本预计 **2–3.5 天**。解码工具的浮点支持、随机读取和打包是主要不确定项，先在 S0 暴露，避免最后再返工。

## 10 首轮实装记录（2026-10-03）

本地开发版 `0.5.0-dev.storage.1`，XLD `core.71`。本轮完成 S1 副本优化；S0 中输入去重与浮点播放保真已验证，WavPack/FLAC 编解码实验尚未开展，S2/S3 未开始。压缩收益没有计入以下结果。

- 新细分结果使用 schema 3：基础分轨来源保存 target/residual 两份 FLOAT WAV；原输入引用具体父 run、声部和采样区间。原曲来源保留解码后的 original.wav，避免不同压缩音频解码器产生差异。
- 试听复用现有分块 PCM 播放器，最多 64 MiB PCM 缓存，动态应用三路共同增益。时间轴混音继续读取 raw 文件，不重复施加试听增益；这不是 S2 的磁盘解码缓存。
- 存储管理新增单组“优化副本”：先逐块比较原输入和父轨采样，完全一致才引用父轨；不一致保留原输入。可取消校验；提交新记录后清理失败会保留有效结果，支持再次清理。
- 默认沿用回收站模式，清空回收站后才释放磁盘空间。选择永久删除时弹出具体曲目与副本体积确认。已保留/被 MIDI 使用的结果仍可优化副本，但不能整组误删。
- 元数据迁移记录保存在 `refinement/storage-optimization/<runId>.json`，不改 target/residual 路径、字节或 mtime。原模型结果、MIDI、草稿、人工修订、保留标记继续有效。旧 schema 2 可读；已转换结果需要新版 XLD。

实测《100 years of choke / 百年の窒息》隔离副本：1,744,244,094 → 581,414,942 字节，约 **1.62 → 0.54 GiB，减少 66.7%**。target/residual 整文件 SHA-256 不变，已有弦乐 MIDI 仍可读取。测试使用硬链接构造独立目录，以上为结果目录的逻辑体积变化，不能解释为本轮已释放相同的物理空间；正式资料库 940 个文件未迁移。

验收包括完整 Node 回归、实际 Python 保存流程（替代模型推理）、真实样本迁移、Electron 原生 WebAudio 渲染，以及打包版界面的试听/循环/原曲切换/存储操作/语言切换。未重新运行 GPU 模型推理，未做无开发环境机器部署验证。
