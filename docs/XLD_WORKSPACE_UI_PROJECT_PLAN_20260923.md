# XLD 工作台界面整合项目企划书

- 日期：2026-09-23；版本：v1.0。
- 状态：workbench.8/core.69 已完成前三轮实装与第四轮核心流程验收；部分模型/管理分支及正式发行仍待补。见[53项验收记录](../work/workbench-review-20260923/FEATURE_ACCEPTANCE.md)。
- 开发基线：`releases/0.5.0-dev.tracklayout.3`；XLD `0.5.0-dev.core.65`，XML `0.5.0-dev.stems.13`。
- 基线交接：[R17 轨组与轨头控件](../work/track-layout-20260923/HANDOFF.md)。
- 执行方式：个人项目，复用现有界面控制器和后台，分四轮形成可运行开发包。
- 本轮最高约束：**现有功能不能丢。每项已有能力必须有新入口、保持原有行为，并能用实际操作验证。**

## 1. 目标与完成定义

把当前“概览、段落、和弦、分轨、转谱、时间轴”六个并列页签，整理为以时间轴为中心的工作台：左侧选歌，中间看轨道，轨头控制试听，右侧处理当前对象，底部统一播放。

高频路径：

**选歌 → 看时间轴 → WAV/MIDI 对照 → 聚焦声部 → 修正音符 → 保存修订 → 全曲复听 → 导出或融合。**

低频的模型配置、历史结果、存储清理按需展开。减少来回换页和常驻控件，不减少能力。

完成条件：

1. 现有结果直接可用，不重算音频、不迁移或重写用户数据。
2. 第 4 节功能清单全部有入口和验收记录；后台尚有接口但界面无法操作，也算功能丢失。
3. 标准宽屏下，默认折叠的七个声部、分析条带和播放器能处于同一工作视图。
4. 打开、关闭或切换属性面板，不打断播放，不丢选区、缩放、草稿和任务状态。
5. 生成、试听、编辑、保存、版本切换、融合和导出的结果保持一致。
6. 有独立开发包和回退入口；现有 tracklayout.3 保留。

“单屏”指常用工作视图。展开大量子轨、深度编辑、长版本列表和模型对照可以在各自区域滚动，不以缩小文字或隐藏功能强行塞满一屏。

## 2. 预览与正式实现的关系

本会话的 `xld-workbench-preview` 只作为空间布局和交互方向的参考。示例音符、波形、段落、数量和按钮反馈不是真实分析结果，不复制其模拟播放、存储或编辑实现。

预览没有展示全部功能。实装时必须补回：一键 MIDI、所有适用的备选模型、细分三方试听、任务取消和日志、草稿恢复、完整版本管理、轨下演奏方式/和声关系、精确循环、重做、恢复原始、播放器切歌/随机/重复、目录与 XML 接口等。详见第 4 节。

预览里的“勾选声部导出”不视为已存在能力或本轮授权新增能力。当前输出继续是：

- **导出当前声部 MIDI**：导出该声部已保存的完整文件，包含其内部乐器。
- **融合整曲 MIDI**：沿用当前全部有效活动声部及已有跳过规则。
- 当前内部乐器、选区、任意勾选声部导出留待后续单独设计。

本轮不改变模型默认、可用后端、识别算法、缓存格式和文件许可策略。已经停用的模型不重新上线；已有历史结果继续可读取、查看和按现有规则清理。

## 3. 页面结构与操作约定

### 3.1 界面区域

| 区域 | 常驻内容 | 按需展开内容 |
|---|---|---|
| 顶栏 | 品牌、分析、结果、导出、设置入口 | 帮助/关于、语言、字号、路径设置 |
| 左侧曲库 | 专辑/曲目切换、搜索、当前曲目 | 专辑播放/随机、专辑批量分析、刷新和更换曲库 |
| 曲目栏 | 曲名、艺人、定位曲目、简短结果状态 | 原概览的完整状态摘要、刷新结果、XML 同步状态 |
| 中央时间轴 | 段落、和弦、WAV/MIDI 行、选区与光标 | 单轨聚焦、子轨展开、深度音高和时间导航 |
| 轨头 | 名称、折叠、排序、WAV/MIDI/关闭、M/S | 音量、源文件、模型、活动版本、重新生成、打开目录 |
| 右侧面板 | 当前轨道/音符/标注的属性 | 分析配置、结果版本、草稿、导出选项；同一时刻一个主面板 |
| 底部播放器 | 播放/暂停、切歌、位置、总音量、当前音源 | 随机/重复、循环详情、定位原文件等低频操作 |
| 任务入口 | 有任务时显示所属歌曲、阶段、进度、取消 | 日志、批量计划/完成数/跳过或失败原因 |

段落和和弦的模型对照保留完整结果视图。可以从“结果 → 段落/和弦 → 对照”展开宽视图，继续使用已有对照绘制逻辑；不能用窄侧栏缩略图代替全部功能。

存储管理与全库结果清理继续使用适合长列表的独立面板/对话框。统一入口不等于强行统一底层删除方式。

### 3.2 四个全局入口

- **分析**：段落、和弦、分轨、转谱。分轨内保留基础分轨与目标细分；转谱内保留单声部和一键 MIDI。模型仍采用“默认 + 备选”，保留适用场景、可用状态、缓存和当前使用状态。
- **结果**：本曲摘要、各类结果、MIDI 版本、人工修订、草稿、模型对照、目录；向下进入存储管理和全库清理。
- **导出**：当前声部 MIDI、整曲融合 MIDI、打开融合文件/目录，以及现有 Music Lab 接口更新入口。不改变各命令的输出范围。
- **设置**：曲库与分析目录、语言、字号、帮助和关于。高频的搜索和刷新曲库在侧栏仍可直接找到。

从轨头进入模型或版本时，自动带入当前歌曲和声部，不要求用户再选一遍。全局“分析”和“结果”可以更换处理对象，但必须明确显示对象。

### 3.3 选中对象、面板与任务

- 时间轴是主工作区；首次无歌曲时显示选曲入口，选中但尚无结果时显示相应生成入口，不能出现只有空白轨道的页面。
- 选择音符时，属性内容跟随该音符；选轨头时显示声部来源、版本和音量；标注模式下显示段落/和弦标注字段。
- 用户主动打开分析、结果或导出面板后，播放光标和普通刷新不得抢走该面板。当前选中对象可在后台更新，通过“属性”返回。
- 关闭面板仅收起界面，不清空选择、退出编辑、撤销草稿或停止任务。
- 保留浏览、音符选择/编辑、圈选循环、人工标注的清晰模式。互斥手势沿用当前规则，不给同一次拖动同时绑定移动音符和跳转播放。
- 分析任务绑定启动时的曲目和来源。切换歌曲或面板后仍显示真实任务所属对象，不误标为正在分析当前新歌曲。
- 错误显示在有关操作旁；详细堆栈留在日志。不可用按钮必须说明缺少音源、模型、选中对象，或存在未保存草稿等实际原因。

### 3.4 必须区分的状态

| 状态 | 界面应表达的含义 |
|---|---|
| 准备运行的模型 | 下一次生成会使用哪个模型 |
| 已保存结果/历史版本 | 哪些文件可选、可回退、可清理 |
| 当前活动版本 | 时间轴、融合和导出实际使用的已保存结果 |
| 未保存草稿 | 当前试听/编辑中的变化，尚未成为已保存修订 |
| 监听来源与 M/S | 当前听什么，不决定导出哪些声部 |
| 折叠与显示顺序 | 当前怎么看，不改变 MIDI 乐器归属或音频文件 |

保留 `ok`、来源有效性和模型版本匹配的现有区别。人工修订不能因为模型身份不匹配而被显示为损坏或被排除。

| F49 | 全库结果清理、模型过滤、碎段查看、选择/批删 | 结果 → 全库清理 | 继续区分自动结果、原曲和人工数据；保留原回收站规则 |
| F50 | WAV 存储扫描、体积、搜索/筛选、批选、保留、目录 | 结果 → 存储管理 | 关联细分/MIDI 的保护、活动源批选规则、忙碌状态保持 |
| F51 | WAV 回收站/永久清理，原有确认与错误反馈 | 存储管理 | 删除边界不扩大；“进入回收站”不误报为已实际释放空间 |
| F52 | Music Lab manifest、手动更新接口、XML 跳入对应歌曲 | 曲目摘要、导出与原内部跳转 | XML 仍消费同一 XLD 结果；内部导航重定向后能到新入口 |
| F53 | 原有快捷键、每曲折叠/排序、本机偏好、重开恢复 | 对应新控件与现有存储 | 保留持久化范围；监听设置不擅自变成跨曲共享设置 |

发现表外的现有有效入口时，先补清单，再迁移；不得因为预览没有画出它而直接删除。静态 HTML 中已经退役或运行时隐藏的历史入口，须结合控制器判断，不因“源码存在”就重新开放。

## 5. 保持原有数据和播放逻辑

本轮新增的主要是导航、面板和上下文绑定，底层沿用已验收实现：

1. 曲目、分轨来源、MIDI 运行、内部乐器、音符的身份不变。父 WAV、MIDI 内部乐器、显示轨组继续分开。
2. 原 WAV 和模型 MIDI 不覆盖；人工标注、草稿、人工修订分开保存；不迁移分析目录。
3. UI 不重新实现来源有效性、版本激活、删除保护、融合范围或 MIDI 写入规则。
4. 保留单一播放控制与现有 AudioContext 调度；开关面板和切换观察焦点不创建第二套播放器。
5. `sourceAudio.key` 继续用于已有来源身份，`streamKey` 用于音频缓存。不能因界面改名而互换。
6. 折叠/排序只改显示；跨 guitar/strings 改归属、跨乐器批量修订不在本轮范围。
7. 草稿变化沿用现有暂停/保留光标规则；导出和融合不得悄悄绕过未保存提示或自动丢草稿。
8. 现有 MIDI 使用真实秒位置；不新增拍号、速度推断或量化，不把文件固定速度展示为分析结果。
9. XML 继续负责可视化；分析和修订仍归 XLD。保留 XML 侧对人工修订的保护。

## 8. 验收方案

### 8.1 功能完整性

- F01–F53 全部有新入口；以真实运行时行为为准，不只检查按钮文本或 DOM 是否存在。
- 入口状态正确：未选曲、未分析、仅 WAV、仅部分 MIDI、完整结果、人工版、历史版、相关草稿、处理中、失败/取消、来源缺失。
- 默认和备选模型列表来自现有后端；停用模型历史结果仍能查看，不能因界面优化丢失。
- 未实现能力不出现能点击但无实际作用的正式按钮。

### 8.2 核心操作场景

| 场景 | 操作 | 通过标准 |
|---|---|---|
| 无结果曲目 | 选歌，进入分析，查看各层依赖 | 空态有下一步；不能误报可用 MIDI 或打开错误目录 |
| 已有完整结果 | 打开 MEGURI，切换分析/结果/属性，收起两侧 | 无需重新分析；位置、缩放、选择、监听组合保持 |
| 分轨与细分 | 切基础模型，选细分目标/范围，三方试听，取消 | 配置完整；试听不叠播；整曲和预览身份清楚 |
| 单声部与一键 MIDI | 看计划，运行、部分失败或取消，打开结果目录 | 状态与已完成文件一致；有效输出目录不错误置灰 |
| 轨组 | 折叠、展开、父组排序、子轨排序、键盘排序 | 音符总数/原属乐器不变；重开恢复顺序 |
| 混播 | WAV/MIDI/关闭、M/S、多独奏、音量、预设、原曲 A/B | 父子规则、纯 WAV、互补替换、共享时钟正确 |
| 导航和循环 | 深度缩放、音高滚动、定位光标、精确循环、切面板 | 控件与实际播放一致；视图保持可操作 |
| MIDI 修正 | 新增/选择/拖动/边缘调整/精确字段/删除 | 只修改目标乐器；原检查和快捷键保持 |
| 合并与拆分 | 预览、取消、应用、撤销、重做、试听 | 不应用不改草稿；一步操作可完整撤销 |
| 草稿和修订 | 切面板、刷新、重开、换源、返回草稿、保存 | 无静默丢失/错误归属；机器原件不变 |
| 版本和删除 | 切模型版/人工版、保留/回退/删指定版、打开目录 | 活动版本、音源、时间轴与目录同步；保护规则不变 |
| 输出 | 有草稿时导出/融合；保存后再执行 | 相关草稿正确阻挡；声部导出字节一致；融合含活动修订 |
| 标注与条带 | 图上/表单标段落和和弦；切演奏方式/和声关系 | 同一人工标注层；模型结果不被覆盖；依据与限制可见 |
| 清理 | WAV、MIDI、段落/和弦分别进入对应清理入口 | 范围明确，依赖和保留保护有效，不动原曲/其他人工数据 |
| XML 联动 | 从 XML 定位曲目、读取/更新分析结果 | 原契约和人工修订保护仍通过 |

删除、修订和融合的写操作只用隔离夹具或样本副本验收，不在用户真实分析目录做破坏性测试。真实数据用于读取、显示和用户主动听评。

### 8.3 布局与性能

- 优先检查 1600×900、1280×800；补查用户实际高分辨率窗口、当前 Windows 缩放和软件字号选项。
- 普通轨高以约 48–64 px 为初始范围，轨头约 150–180 px；最终按真实内容调整。聚焦音高行保持原编辑精度。
- 默认折叠的主视图和播放器完整可见；长列表局部滚动；窄窗口可收起曲库/面板，不能以截掉关键按钮解决拥挤。
- 中英文本、长曲名、长模型名有合理换行/截断详情，关键状态和禁用原因可读。
- 保留固定轨头、视口渲染、有界音频缓存；面板切换不重复绑定事件，不额外触发模型推理。
- 用同一真实曲目、片段和窗口，对比基线与新包的滚动/缩放/播放；无明显退化。自动调度检查与用户实际听感分别记录。

### 8.4 复用的验证入口

先运行受影响范围，再在最后一轮跑完整发布前回归；无新失败或改动不反复跑重模型。

- XLD：现有 `npm test`，以及 `test:workspace:ui`、必要的 MIDI/分轨/融合窗口检查。
- 音频与编辑：现有 playback、multi-midi、hybrid-mix、timeline-view、track-layout、midi-edit、note-shape、draft/export/merge 测试。
- CPU 文件回读：原 MIDI 修订、融合和音符形状验证；模型识别本身不因布局调整重训或重跑整曲。
- XML 和发行工具：沿用 R17 回归链，确认接口和包内文件对应。
- 打包后用独立进程完成一次完整保存、重开、回退、导出和融合路径。

当前测试脚本中存在开发机 Electron 绝对路径。执行时使用实际配置的运行环境；本轮不借界面优化重建全套工具链。静态测试若绑定旧 DOM/旧页签，改为验证对应行为，不能只删除失败断言。
