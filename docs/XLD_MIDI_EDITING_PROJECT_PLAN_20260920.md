## 1. 项目定位与目标

XLD 定位为可持续接入研究模型的本地音乐分析工作台，覆盖分轨、转谱、结构观察与人工修正；XML 消费分析结果并承担音乐可视化。

本阶段对标 RipX 的“分离与识别之后能够修正、核对、导出”的使用流程。保留项目的模型选择能力，并补齐自动识别结果进入实际使用之前的人工环节。

核心流程：

**模型生成初稿 → 对照声部 WAV 试听 → 修改 MIDI 音符 → 保存人工修订版 → 继续分析、融合与导出。**

第一版的成功标准：用户能够在 XLD 内修好一段识别不佳的 MIDI，保存并重新打开后，听到、看到、导出的都是同一份修订结果。

## 2. 背景与现有基础

### 2.1 当前问题

1. 部分声部转谱存在错音、漏音、音符起止不准和持续音碎裂。
2. 更新模型可以改善初稿，但不能保证每个曲目、每个区间都正确。
3. 目前时间轴能展示音符，人工标注主要针对段落与和弦，尚未形成音符级编辑流程。
4. MIDI 试听与精细修正仍依赖外部软件，用户需要在不同工具间搬运结果。
5. 引入人工修改后，必须明确模型原稿、人工版与当前使用版本，避免融合、显示、导出各用一份结果。

碎音的来源可能包括转谱边界错误、揉弦或滑音、分轨残留，也可能是真实重复演奏。不能预设所有相邻短音都应合并。

### 2.2 可直接利用的基础

| 已有能力 | 本阶段的利用方式 |
| --- | --- |
| 曲库与曲目身份 | 所有编辑继续挂在原曲及其声部下 |
| 基础分轨、Mega53 细分 | 提供校对用的声部 WAV |
| 多声部转谱、一键 MIDI、融合 | 提供模型原稿和后续导出入口 |
| 统一时间轴、缩放、平移、单轨展开 | 扩展出音符修正模式 |
| 段落与和弦人工标注 | 保留，与音符编辑分开操作 |
| MIDI 版本切换、保留与删除 | 扩展人工修订版的读取和选择 |
| 演奏方式与和声关系条带 | 对当前选定的修订 MIDI 重新计算 |

已有能力继续使用；每一轮实施前核实实际状态，避免重复建设。

## 3. 范围与边界

### 3.1 本阶段包含

- 应用内 MIDI 校对试听。
- 钢琴卷帘上的音符级修改。
- 人工修订结果的保存、回退、导出和融合。
- 后续分期增加批量纠错、鼓轨编辑、外部 MIDI 往返与演奏表现编辑。

### 3.2 后置内容

- 对原 WAV 做音符级变调、修复、谐波编辑或音频重合成。
- 完整 DAW 的录音、混音器、插件宿主与自动化系统。
- 新增声源细分工程或自研转谱模型。
- 默认节拍检测、自动量化和未经确认的全曲纠错。
- 跨曲比较、完整动机识别与大型曲库检索。

修改 MIDI 音符只改变音符数据，不会自动删除或改变 WAV 中的对应声音。RipX 的音频级编辑属于更大的独立工程，后续另立项目评估。

## 4. 用户场景

| 场景 | 用户操作 | 期望结果 |
| --- | --- | --- |
| 弦乐持续音被切碎 | 循环试听，选择确认属于同一持续音的碎片，连接并调整尾部 | 持续音在 MIDI 中连贯，真实重复起音仍保留 |
| 吉他出现错误音高或杂音 | 对照 WAV，删除杂音，移动错音 | 局部音符更接近实际演奏 |
| 转谱漏掉几个音 | 在指定时间与音高位置补音 | 不需要重新跑整首模型 |
| 鼓的类别识别有误 | 把选中音符改到正确鼓类别 | 节奏时间保持，鼓类别正确 |
| 新模型效果不如人工版 | 生成新的独立模型结果，再选择是否使用 | 人工修订不被覆盖 |
| 需要大量编辑 | 导出到 FL Studio，完成后导回并核对对齐 | 修订结果仍可参与 XLD 分析 |

## 5. 分期需求

优先级：P0 为第一版必需；P1 为第二轮；P2 为第三轮及之后。验收以工作流是否可用为准，不以按钮数量为准。

### 5.1 第一轮：单轨修正流程（P0）

| 编号 | 功能 | 最小范围 | 验收要点 |
| --- | --- | --- | --- |
| E01 | MIDI 试听 | 单轨、当前选定版本、基础试听音色；暂停与跳转 | 音符与播放位置对应，暂停或跳转后没有挂音 |
| E02 | WAV / MIDI 对照 | 在同一曲目时间位置切换；原曲可作为补充参照 | 切换不从头播放、不改变速度、不移动片段位置 |
| E03 | 区间循环 | 选择区间、启停循环；与“标注”模式区分 | 循环范围明确，边界处发声和停止行为稳定 |
| E04 | 选择与属性 | 单选、多选、框选；显示音高、开始、结束和力度 | 看得清选中了什么，多选时修改范围明确 |
| E05 | 基础编辑 | 增加、删除、移动、修改音高、起止时间与力度 | 鼠标操作和数值输入都可用，禁止负时长等无效结果 |
| E06 | 撤销 / 重做 | 当前编辑会话内可逆操作；一次拖动算一次操作 | 可退回修改前结果，不因鼠标移动产生大量撤销项 |
| E07 | 人工修订版 | 保存、另存、重新打开、恢复原稿；离开未保存草稿时处理 | 原稿文件保持不变，取消离开后草稿仍在 |
| E08 | 使用与导出 | 选择当前有效版本；单轨导出；已有融合读取人工版 | 显示、试听、融合、导出对应同一版本 |

P0 先把单轨流程跑通。多轨 MIDI 同时试听、独奏与静音作为下一轮扩展，不因混音界面扩大首版范围。

试听音源是校对工具。第一版主要检查音高、起音、音长与明显力度差异，不以试听音色是否像原录音判断转谱是否正确。

### 5.2 第二轮：提高纠错效率（P1）

| 编号 | 功能 | 需求范围 |
| --- | --- | --- |
| E09 | 音符连接与拆分 | 对明确选中的音符操作；第一版连接以同音高、同声部为主，结果可预览、可撤销 |
| E10 | 批量编辑 | 整体移调、时间平移、力度修改、音长调整；保留音符间相对关系 |
| E11 | 鼓轨专用编辑 | 按鼓类别分行，支持类别改正、增删和力度编辑 |
| E12 | 多轨试听 | 同步播放各轨、独奏、静音、基础音量；编辑轨道保持突出 |
| E13 | 原稿与修订差异 | 区分新增、删除和修改；避免全曲同时高亮造成噪声 |
| E14 | 模型结果对照 | 同一区间切换已有模型结果；临时对照不自动改变当前有效版本 |
| E15 | 批量与版本协调 | 一键 MIDI 尊重人工版和用户选定旧版；显式重算生成独立结果，不悄悄替换 |

鼓轨试听需注意：镲片等声音的尾音也受音源行为影响，不能将“延长 MIDI 音符”视为修复所有鼓尾音问题的通用办法。

### 5.3 第三轮：外部往返、表现与分析（P2）

| 编号 | 功能 | 需求范围 |
| --- | --- | --- |
| E16 | FL Studio 等外部编辑往返 | 导出单声部或多轨 MIDI；重新导入时选择目标、核对起点和时长，另存修订版 |
| E17 | 演奏表现编辑 | 分期加入踏板、音高弯曲和表情控制；先选择真实需求最强的一项 |
| E18 | 声部整理 | MIDI 音符跨轨移动或拆出独立轨，保留来源；不改变对应 WAV 的分离结果 |
| E19 | 辅助纠错 | 标出疑似碎音、重复音或异常短音；用户逐段确认，不后台自动改写 |
| E20 | 选区摘要 | 音域、发声覆盖、音符密度与和弦关系；注明依据的是哪份 MIDI |
| E21 | 动机与重复标记 | 先支持人工建立原型、变奏、再现关系；自动发现作为后续独立评估项 |

E17 不能仅靠连接音符实现：音高弯曲与多音同时发声的表达需要单独设计，避免编辑一个音却影响同通道其他音。

## 6. 交互设计

### 6.1 入口与布局

- 沿用现有时间轴，不新增独立大型编辑页面。
- 全曲视图负责定位；点击声部轨头进入单轨细读。
- 工具模式明确区分“浏览”“标注”“修正”。修正模式内也可平移、缩放和设置循环，不与段落标注混用。
- 顶部保留模式、撤销、重做、保存等常用操作；选中音符后才出现适用的编辑工具。
- 右侧使用可收起的属性面板；窄窗口下可折叠，优先保留读图区域。
- 底部展示当前试听来源、声部、版本及未保存状态。

### 6.2 编辑约定

- 所见位置以歌曲真实时间为准，默认不量化、不强制拍点吸附。
- 提供拖动与精确数值输入两条路径。
- 保存后继续停留在当前区间，不跳回全曲开头。
- 第一版撤销历史保留在当前会话；重新打开加载已保存版本，不要求持久化全部操作历史。
- “恢复原稿”切换或恢复到原稿状态，不删除已经保存的人工版。
- 显示“模型原稿”“人工修订”“正在使用”“未保存”等可理解状态，技术版本信息放详情。

### 6.3 模型菜单精简

后端继续允许替换，日常界面仅保留默认方案及有明确用途的备选。已淘汰模型不占用主界面，已有结果仍可读取。

MSAF 等模型的退役、运行环境卸载、历史结果删除属于三个不同操作，应在单独清理任务中检查依赖。本企划书不自动授权删除任何模型或结果。

## 7. 数据与模块关系

### 7.1 最小数据关系

**曲目 → 声部来源 WAV → 模型原稿 → 人工修订版 → 当前选定版本 → 融合 / 导出 / 分析。**

每份人工修订至少关联：曲目、声部、父版本、来源音频身份、创建时间和结果内容身份。复用现有版本记录与读取方式，不先建设通用插件平台或新数据库。

### 7.2 保存与读取规则

1. 模型原稿保持只读，修订版独立保存；不就地修改模型生成的 MIDI 和记录。
2. 编辑对象应拥有稳定音符标识，方便选择、撤销和差异显示。
3. 现有时间轴音符数组是显示数据，不能把它当作完整 MIDI 文件的全部内容；保存时保留未编辑的轨道、乐器、通道、踏板、音高弯曲和速度事件。
4. 若某种数据暂不支持无损往返，应明确限制该操作，不能保存成功后悄悄丢掉数据。
5. 保存新版本成功后再切换当前使用版本；保存失败时原稿、上一有效版和编辑草稿仍可访问。
6. 预览读取当前草稿；正式导出与融合使用已保存、明确选定的版本。存在未保存编辑时说明使用哪份结果。
7. 时间轴、版本菜单、融合和导出共用“当前有效版本”的读取约定，避免各自猜测。
8. 人工版及其必要来源纳入已有保留与删除保护；自动保留策略不得将人工版当作重复模型结果回收。
9. 更换源 WAV 后保留旧修订及其原有来源关系，显示来源已变，不自动套用到新音源。
10. 人工版的改动使旧融合缓存不再代表当前结果，应生成新的融合结果；既有结果仍可保留。

### 7.3 时间与分析一致性

- 内部编辑以真实时间对齐音频；MIDI 的速度图、导出时间换算与音频起点必须保持一致。
- 固定 MIDI 容器速度不等于测得的歌曲速度，不据此生成分析结论或强制量化。
- 修改音符后，刷新依赖 MIDI 的演奏方式和声部和声关系。
- 修改 MIDI 不改写音频模型识别的段落、和弦；它们作为独立参照层保留。
- XML 继续消费 XLD 提供的结果，不承担音符编辑、模型调度或修订版本选择。
- 人工 MIDI 或和弦修订如何进一步驱动 XML，按现有接口单独验证，不因加入编辑功能顺带重构可视化。

### 7.4 建议职责分配

| 部分 | 职责 |
| --- | --- |
| 时间轴界面 | 命中音符、选择、拖动、属性输入与状态展示 |
| 编辑逻辑 | 草稿、稳定标识、操作规则、撤销与重做 |
| 试听逻辑 | MIDI 调度、音源发声、WAV 对齐、循环与停止清理 |
| 现有结果服务 | 修订版读写、来源关联、当前版本、导出和保留策略 |
| 转谱后端 | 继续只生成独立模型结果，不直接修改人工草稿 |

具体文件拆分由实现时决定，以少量模块为限；优先复用现有结构。

## 8. 开发顺序与交付物

| 里程碑 | 交付内容 | 进入下一步的条件 |
| --- | --- | --- |
| M0：小范围验证 | 选定一段 MEGURI 弦乐；验证应用内 MIDI 发声和 MIDI 保存后重新读取 | 时间对齐可用，既有事件不被无故丢弃 |
| M1：编辑基础 | 单轨选择、增删、音高和时间调整、属性输入、撤销重做 | 能完成指定几处错误的修改，交互不会误触其他音符 |

| M3：效率迭代 | 连接拆分、批量操作、鼓轨、多轨试听、差异与模型对照 | 用户确认确实减少重复操作 |
| M4：逐项扩展 | 外部编辑往返、表现控制、声部整理、选区分析 | 每次只选一个收益明确的功能交付 |

启动前核对最新版本交接，处理会阻断本轮流程的现有问题，特别是当前版本显示、一键任务选择、弦乐来源变化和融合读取。不得把历史交接中记录的问题直接当作最新版本仍未修复的事实。

## 9. 验收方案

### 9.1 首版真实曲目验收

主要样本：MEGURI 的一段弦乐，建议选择 30—60 秒、包含明显持续音及若干可人工确认错误的区间。现有完整曲目结果继续作为基线，测试在副本或独立修订中进行。

1. 从现有时间轴进入弦乐单轨视图并定位该区间。
2. 同位置切换 WAV 与模型 MIDI，确认问题。
3. 至少完成删除错音、补音、修改音高和调整音长各一项。
4. 撤销再重做，试听结果跟随修改。
5. 保存为人工版，关闭并重新打开，音符内容与时间位置一致。
6. 选择人工版参与导出与融合，确认生成文件使用了修订内容。
7. 切回模型原稿，原始音符与文件保持完整。
8. 重新生成模型结果，人工版仍保留，当前使用版本不会在未明确选择时被替换。

### 9.2 必要检查

| 检查点 | 合格条件 |
| --- | --- |
| 原稿保护 | 编辑及保存前后原稿文件内容不变 |
| 时间精度 | 保存、重开、导出后无可感知整体漂移；自动往返检查采用毫秒级容差，并记录格式精度限制 |
| 停止与跳转 | 暂停、跳转、循环退出、切轨后无持续挂音和重复调度 |
| 基础数据保留 | 未修改的乐器、轨道和 MIDI 表现事件保留；专门检查含踏板或弯音的样本 |
| 撤销与重做 | 操作序列回退和恢复一致；一次拖动对应一次操作 |
| 失败处理 | 写入失败不破坏上一有效版，不虚报保存成功 |
| 版本一致 | 时间轴、菜单、试听、导出和融合使用版本一致 |
| 长曲体验 | 使用 MEGURI 全曲与密集声部检查缩放和选择，不要求每次拖动重绘所有轨 |
| 旧结果兼容 | 无人工版的旧曲目照常读取、融合和导出 |

优先测试会造成数据丢失、时间错位或结果错误的路径。可逆的布局和文案调整以实际界面检查为主，不为每个按钮重复建立镜像测试。

补充曲目可使用现有 toe、BCNR 测试材料及自制简单 MIDI，用于区分界面问题、音源问题与转谱问题。验收材料保留在本地，不随公开源码发布。

## 10. 风险与控制

| 主要风险 | 本项目采用的处理方式 |
| --- | --- |
| MIDI 音色差异被误认为识别错误 | 标明试听来源，先核对音高、时序和持续时间，再评估音色表现 |
| 连接操作抹掉真实重复演奏 | 先做手动、局部、可撤销操作；自动建议放后期 |
| MIDI 保存只保留可见音符，丢掉其他事件 | 完整保留未编辑数据；通过表现事件样本验证往返 |
| 模型重跑或自动清理损伤人工版 | 独立版本身份与保留保护，修改前加入针对性回归验证 |
| 外部 DAW 改变速度或起点 | 导回时核对时间范围和速度信息，预览对齐后另存，不覆盖原版 |
| UI 功能过多再次变稀疏或拥挤 | 单轨编辑、上下文工具、可折叠面板，按阶段开放 |
| 播放或音源依赖影响发布 | M0 先验证 Windows 打包可用性；使用有明确分发许可的试听资源，或明确用户自配方式 |
| 项目扩大成完整 DAW | 用阶段验收限制范围，音频重合成、录音和插件宿主另立项 |

## 11. 公开发布与维护

- 自有代码延续已确认的 MIT 许可，第三方组件及音源保留各自许可。
- 不随项目上传模型权重、用户音乐、分轨结果、MIDI 成品或账号凭证。
- 模型适配与音符编辑分开演进；新增后端输出仍进入统一结果流程。
- 将“模型原稿可读、人工版可保存、时间不漂移”作为后续升级的基本检查。
- 开发版先完成本机试玩；面向第三方标称正式可用前，再验证干净 Windows 环境。
