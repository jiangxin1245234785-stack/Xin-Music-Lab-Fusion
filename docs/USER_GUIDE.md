# 快速上手与常见问题

[返回首页](../README.md)

本指南说明当前工作台的用法。**目前还没有通用下载安装包**：以下步骤面向已获得开发者协助、程序与分析环境均配置好的试用者。只下载 GitHub 源码不能直接完成这些操作。

## 1. 打开正确的程序

打开完整程序目录中的 **XLD.exe**，进入分析工作台。**XML.exe** 是可视化入口。

不要只复制一个 EXE；应用还依赖同目录资源和另外配置的运行环境。当前开发包包含本机路径，因此也不能仅靠“保持文件夹相对位置”就保证在另一台电脑工作。

遇到“分析环境未就绪”时，先使用随包的 **检查环境.cmd** 或界面的环境状态入口，把诊断结果交给提供测试包的人。当前尚无自动修复 / 安装全部模型的向导。

## 2. 选择曲库和结果目录

1. 点击 **更换曲库**，选择自己保存音乐的文件夹。
2. 展开 **资料库**，在“分析资料库”旁点击 **更改**，选择容量足够的结果目录。
3. 在左侧曲库选择曲目。单击选择工作曲目，双击或播放按钮开始播放。

曲库保存原始音乐，分析资料库保存派生结果。建议分开存放，方便备份与清理。第一次试用先处理一首熟悉的歌。

## 3. 分轨与试听

进入 **分轨** 页，先用默认 BS-RoFormer SW 生成基础声部 WAV。完成后选择某个声部试听，或者打开 WAV 目录，在其他软件中检查。

想提取更具体的乐器时，使用 Mega53 细分，选择输入和目标。可以先做 30 秒预览，再决定是否运行整曲。弦乐等细分可以从 other 或原曲开始，具体取决于当前需要分析的内容。

**Mega53 的目标组与子类会重叠。** “弦乐组”和“小提琴”等不是天然互斥轨道，不要把所有输出一起叠加当成原曲重建。

## 4. 生成 MIDI

进入 **MIDI** 页，选择需要转谱的声部，再选择默认或备选模型。

- 吉他先用 MuScriptor Medium；复杂失真和叠奏可以比较 Large。
- 钢琴和贝斯可先沿用默认 HiRes 模型。
- 鼓默认 ADTOF，也可以比较 MuScriptor 两档。
- 弦乐先完成 Mega53 **整曲**提取，然后在“弦乐音源”选择一份结果。默认使用 MuScriptor Large。

点击 **生成 MIDI**。已有符合当前模型与音源的结果时，可以复用缓存；强制重新生成会重新运行该任务。

选择模型卡片本身不表示已经生成，也不一定立即改变用于融合的结果。根据界面提示生成或使用对应 MIDI 后，再查看当前结果状态。

## 5. 一键 MIDI 与融合

一键 MIDI 按各声部已选模型顺序处理可用音源，复用符合条件的缓存，并融合有音符的结果。

基础流程涉及钢琴、贝斯、吉他和鼓；选择了有效的整曲弦乐来源后，也会加入弦乐。声部缺失、结果为空或任务失败时，以一键计划和完成摘要为准，不保证每首歌都有五个有效声部。

一次只选一份弦乐来源，避免把弦乐总组与子声部重复加入。“不加入弦乐”不会删除过去的文件。

导出的 MIDI 可以在 FL Studio 等支持 MIDI 的软件中打开。播放音色取决于接收软件的乐器或音源；MIDI 本身不包含原录音的吉他失真、混响或弦乐音色。

## 6. 找到与清理文件

**找文件：**使用当前结果旁的目录按钮。单声部目录、本曲 MIDI 目录与融合文件的用途不同；如果没有对应有效结果，相关按钮可能不可用。

**清理 MIDI：**在 MIDI 页删除不满意的模型结果，核对声部与模型后移至回收站。随后选择其他模型生成。不要把“删除旧结果”误当成“卸载模型”。

**清理 WAV：**进入 **资料库 → 存储管理**，按歌曲、模型或目标查看体积，把满意结果标为“保留”，选择不需要的结果清理。存在依赖的文件可能受保护，界面会显示原因。

默认移至回收站；Windows 回收站清空后空间才真正释放。永久删除需要另行明确选择。原曲与模型权重不属于这套 WAV 清理操作。

## 7. 查看段落、和弦与可视化

**段落** 页查看结构边界与模型标签，**和弦** 页查看和弦变化。不同分析器可能给出不同判断，特别是在器乐、弱节拍与复杂和声中。

需要音乐可视化时打开 XML。XML 可读取 XLD 的已有结果；从 XML 打开 XLD 处理后，返回并更新结果。

## 常见问题

### 生成完成，为什么换一个模型后显示未生成？

不同模型和音源分别保存结果。A 模型已经完成，不代表 B 模型也有输出。先核对当前声部、源 WAV、弦乐来源和模型。

### 旧模型结果会因为模型更新而消失吗？

当前版本已经区分“旧结果可读取”和“能否当作当前模型的缓存”。旧模型结果可以继续读取，但不应冒充新版结果。完整的同一引擎多版本切换、回退和按运行记录管理还在完善。

### 弦乐或吉他听起来断断续续？

揉弦、失真、混响与串音都可能导致碎音。先检查分轨 WAV，再比较转谱模型。更大模型不保证每一首更好；当前也不是连续演奏表情重建工具。

### 鼓的镲片尾音听起来不同？

鼓键映射、触发时间、敲击密度和播放音源都会影响听感。当前 MuScriptor 鼓主要转换敲击起点，音符时长约 100 ms；不能据此判断模型恢复了原录音的真实镲片衰减。

### MIDI 显示 120 BPM，歌曲就是这个速度吗？

不是。当前导出使用固定时间换算基准来保持音符的秒级位置，未提供整曲真实变速图，也没有默认量化。

### 没有 NVIDIA 显卡可以用吗？

当前尚未完成所有后端的 CPU 或其他显卡验证。能打开界面不等于所有模型都能运行；提供测试包时应附具体的支持范围，不把开发机显存当作通用最低要求。

### 升级要复制哪些文件？

保留曲库与分析资料库，关闭应用，使用新版本的完整程序目录。运行环境及模型是否需要更新应以版本说明为准。`0.5.0-preview.paths.1` 的环境配置已改为相对路径，可将 releases 与完整 runtime（含 addons）一起搬迁并保留层级；旧开发包不自动获得此能力。用户选择的音乐与输出目录不随程序移动，必要时在界面重新选择。预览版首次需自行选择已有资料库。

## 反馈问题

提供应用版本、系统 / 显卡、问题发生在哪一步、选中的声部和模型、错误文字；必要时附去掉个人路径的诊断摘要。除非确有需要且有分享权限，不用上传完整音乐文件。
